# 笔记正文：只留原生主题

编辑器不再提供多套排版主题。写作和阅读统一用原生主题。栏宽只存在这台设备上，用来安排自己的编辑区。字号、行高、正文配色和自定义 CSS 写在账号上，编辑器和公开分享页用同一套。

## 去掉的主题

工具栏里的「编辑器主题」菜单整项移除。下面这些皮肤和版式不再出现，打开笔记时也不再套用：

- 配色：极简青翠、线描翠绿、微信新绿、薄荷清新
- 版式：日暖素笺、青页讲义、夜蓝制图、铅字期刊、陶色时评、琥珀田记、青玉编按、堇色目录、雾色静页、林间手记

版式附带的装饰一起去掉，包括章节编号（如「NO. 01」）、标题装饰线、刊头文字和特定引用样式。笔记正文本身不变。

本机如果存过上述主题（`edgeever.editor-theme`），版式装饰不再套用。颜色按「字体和颜色」里的表迁到对应配色。存过的自定义配色按原生处理。

## 阅读设置

「阅读」分组按这个顺序排列。栏宽点选后立刻作用在这台设备的编辑器里。字号和行高写入账号，编辑器和公开分享一起变。

| 项 | 档位 | 默认 |
|---|---|---|
| 正文宽度 | 标准、较宽 | 标准 |
| 笔记正文字体 | 保持现有列表：跟随系统、霞鹜文楷、霞鹜文楷屏幕版、朱雀仿宋、思源宋体、霞鹜新致宋、思源黑体、西文衬线、自定义 | 跟随系统 |
| 正文字号 | 14、16、18、20 | 16 |
| 行高 | 紧凑 1.5、标准 1.65、宽松 2.0 | 标准 |
| 正文配色 | 原生，加上下面 9 款 | 原生 |

字号、行高、栏宽用固定档位，不用滑杆。正文字号、行高和正文配色不附说明。自定义 CSS 的说明一行：**支持云端同步。** 这项的编辑入口只在桌面设置里。正文宽度的说明一行：**只改变这台设备上的编辑区。**

### 正文宽度

替换现在的「笔记正文布局」。两档都居中。正文宽度只在桌面设置里出现；更窄的窗口本来就是满宽。

| 档 | 大纲打开 | 大纲收起 | 专注模式 |
|---|---|---|---|
| 标准 | 880px | 1200px | 960px |
| 较宽 | 1040px | 1280px | 1120px |

较宽大约每行多十个字。不再提供靠左铺满。

已有的 `edgeever.editorContentAlignment` 这样接，然后不再使用：

- 没有存过，或存的是居中：标准
- 明确存过靠左：较宽

没动过这项的人，今天看到的是靠左铺满。改完之后，新用户和没动过的人进入标准宽度。

### 正文字号

字号存在账号上。Web、桌面编辑器和公开分享使用同一档。标题维持现在相对正文的比例。一级标题是正文的 1.5 倍，二级是 1.25 倍，其余档位按现有比例跟着正文走。行高用倍数，字变大时间距一起变大。复制到公众号时，正文字号写成行内样式。

代码和公式保持等宽，比正文小一档。Markdown 源码模式跟随正文字号。

标题栏、侧栏、工具栏、文档大纲、思维导图和信息图不跟随。

### 行高

行高存在账号上，和字号一起用于编辑器与公开分享。它只改变段落里一行和下一行之间的间距。段距保持现在的 8px，要改段距就写在自定义 CSS 里。复制到公众号时，正文行高写成行内样式。栏宽不进分享页，也不进公众号。

### 字体和颜色

笔记正文字体维持现状：本机选择，内置字体仍可发布到公开分享页，自定义字体名称不发布。

正文配色放在「阅读」里，用固定选项，不用滑杆。每一项右侧有一块该色的圆角矩形，当前选项在收起时也带着。原生用界面前景色。默认是现在的原生配色。另外 9 款按色相分开，每款差一个大色相。选中一款时，只改链接、行内代码、粗体、待办勾选框以及表格浅底色（表头用该款浅底色，偶数行浅底，单元格选中用强调色半透明高亮；表格边框仍用原生中性灰）。空框和划掉的文字仍用原生。正文、标题、引用、分隔线、代码底和代码边框仍用原生。深色模式同样只改这几项，链接和行内代码用强调色，表格表头底色用暗色微弱强调色混溶。界面、侧栏、工具栏、图表和信息图不跟着变。

## 自定义 CSS

自定义 CSS 的用途是公开分享。只在作者自己的编辑器里生效，这份样式表就没有存在的必要。

它跟已发布的正文字体一样，保存在账号上，这个账号发出的公开分享都用同一份。空着的时候，分享页就是原生排版。编辑器里同时预览，作者能在分享之前看到结果。界面、侧栏、工具栏不吃这份样式。

仍只允许字体、字距、颜色、边框、内外边距、对齐、缩进等排版属性，丢掉 `url()` 和会逃出正文的规则。`font-size` 和 `line-height` 不再接受，这两项只由字号和行高档位决定，避免样式表和档位各改一次。分享页把样式锁在文章正文上，不作用到分享页的标题栏和页脚。复制到公众号时，`h1`、`p`、`blockquote` 这类纯标签规则继续写成行内样式。

长度上限改为 8 KB。现在的 2000 字只是本地主题文件里这个字段的输入上限，输入框和导入校验都卡在这里；整份主题文件另有 64 KB 的上限。2000 字写不下标题、段落、引用、列表和表格各自的规则。8 KB 足够写完这些，放在账号上随分享页下发也仍然很小。

今天这段 CSS 只存在这台设备上，而且选中原生主题时不生效。本轮把字号、行高、配色 id 和 CSS 一起写成账号字段，并在编辑器和分享页上生效。放在同一次新 migration 里，不改已经执行过的旧 migration。未设置时字号是 16、行高是 1.65。

换电脑不丢，靠的是这份账号数据，不做导入导出。Web 和桌面登录同一个实例后读写同一份样式表：一台机器上保存，另一台打开就是最新内容。账号上还没有样式、而这台设备里留着旧的本地 CSS 时，用本地那份填上账号，避免第一次同步把已经写好的样式清掉。之后以账号上的为准。

作者若要对外改段距、字距、首行缩进或标题样式，写在这份 CSS 里。字号和行高不写在这里。空白时编辑框放一份预置：一条声明一行，按正文、标题、链接、强调、代码、引用、列表和表格分组。每组浅色写颜色和间距，对应的 `:root.dark` 紧跟在后面，只覆盖颜色。对话框里的样张用同一套过滤预览草稿，浅色和深色只切换样张，不改应用主题，也不写入账号。恢复预置把草稿放回这份初始值，保存后才写入账号。复制到公众号时只带浅色的纯标签规则。

## 作用范围

栏宽作用于 Web 和桌面的编辑区，只给作者自己看。分享页保持自己的文章卡片宽度。

字号和行高作用于 Web、桌面编辑器和公开分享。复制到公众号时，正文带上同一档字号和行高。「复制到公众号 / 博客」不再套用铅字期刊等版式。链接、行内代码和粗体跟账号上的配色走。自定义 CSS 里的纯标签规则继续写进复制结果，其中的字号和行高声明被丢掉。

iOS 和 Android 的编辑器保持现在的 16px 与对应行高，本轮不改。手机浏览器打开公开分享时，看到的是账号上的字号和行高。

## 保持不动

- 界面字体、界面语言、界面主题
- Markdown 源码的代码高亮主题
- 图表主题
- 笔记正文里已经写入的文字、标题和样式

## 回退

栏宽在本机。删掉对应记录即回到标准宽度。账号上的字号改回 16、行高改回 1.65、配色改回原生、清空自定义 CSS 后，编辑器和公开分享都回到原生排版。主题菜单移除后，旧的主题 id 只用来迁到上表的配色，不改笔记数据。
