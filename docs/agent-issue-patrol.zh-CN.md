# Issue 巡检执行细则

[PR 跟踪评审](agent-pr-review.zh-CN.md)

每次读取本细则和根目录 `AGENTS.md`；项目通用规范不在此重复。目标仓库、工作路径、时间和授权以调用配置为准。本细则仅维护中文版。

## 巡检范围

- 首次检查最近 24 小时新增或更新的 Issue；之后从上次成功扫描位置继续，完整分页、按 ID 去重，并核对未完成 Issue 的新回复、重开、关闭和关联 PR。
- 扫描成功才推进时间；处理失败的项目保留待办，不因推进扫描时间而遗漏。
- 已有 PR 处理同一问题时，核实覆盖范围后交给 PR 跟踪评审，避免重复实现。

## 处理规则

| 类型 | 动作 |
| --- | --- |
| 已确认的低风险 bug | 按授权修复产品代码，完成必要验证后提交、推送，提交关联 Issue。 |
| 信息不足 | 一次性询问关键复现材料。 |
| 高风险或验证不足 | 提供诊断、影响、方案及验证缺口，等维护者审阅后再修改。安装器、自动升级、存储、认证、迁移的机制或配置均属高风险。 |
| 功能改进或新增建议 | 评估产品价值、现有替代能力、实现及维护成本，简短回复结论；不自动实现、不承诺排期。 |
| 使用问题 | 提供具体帮助；确认属于 bug 时重新分类。 |

回复和提交、推送权限由调用配置明确授予。不自动关闭 Issue、发布或部署；关联提交避免使用自动关闭关键词。推送成功后回复提交链接和实际验证结果，说明尚未发布或部署。没有新信息不重复回复。

## 跨次进度与工作区协调

状态保存在调用方指定目录；默认使用 Git common directory（`git rev-parse --git-common-dir`）下的 `agent-patrol/`，按目标仓库分目录，使用 `issues.json`。状态不入库，换 Agent 时交接同一目录。

记录扫描时间，以及每个 Issue 的已读更新时间和评论 ID、分类、关联 PR、待办、修复提交、验证结果、已发回复 ID。提交、推送、回复分别记录；超时先核实是否成功再重试。状态丢失时从 GitHub 历史恢复，避免重新发言。

同一任务使用独占锁防止重叠运行，状态原子写入；工作区写入与 PR 任务共用状态目录中的 `workspace-write.lock`。已有改动、分叉、并发修改或推送冲突时暂停代码写入，继续只读评估，不自行清理现场。遵守调用方的本地分支政策。

## 运行结果

按调用方语言简报：Issue 链接、处理结果、提交或回复链接、验证缺口、待办及需要决定的问题。无变化时简短说明。GitHub 沟通语言、风险评估及平台验证要求遵守 `AGENTS.md`。
