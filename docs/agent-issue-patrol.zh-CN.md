# Issue 巡检执行细则

通用规则见 [GitHub 协作](../AGENTS.md#github-协作) 和 [巡检共用约定](../AGENTS.md#巡检共用约定)。

## 巡检范围

- 首次检查最近 24 小时新增或更新的 Issue。之后从上次成功扫描位置继续，并复查未结项。
- 已有 PR 覆盖同一问题时交给 [PR 巡检](agent-pr-review.zh-CN.md)。

## 处理规则

- 经复现、代码或测试确认的低风险 bug，完成风险评估后应在本轮按授权直接修复产品代码并验证。验证通过后按授权提交、推送和回复。关联提交避开自动关闭关键词，回复附提交链接、验证结果及发布状态。
- 同一 Issue 同时包含 bug 和功能建议时，逐项判断并按各自规则处理。
- 高风险或验证不足的改动先给诊断、方案和验证缺口，等维护者审阅后再改。
- 值得做的功能建议给出最小范围、实现路径、兼容风险和验收标准。已有回复缺方案时补一次。实现和排期由维护者决定。

## 状态记录

`issues.json` 分别记录提交、推送和回复进度，保存已读更新时间和评论 ID、分类、关联 PR、待办、修复提交、验证结果和已发回复 ID。
