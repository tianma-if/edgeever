# 本地化（i18n）

[English](i18n.md)

跟踪 Issue：[#606](https://github.com/tianma-if/edgeever/issues/606)。目标：新增语言只需改词条目录，不改业务代码。

## 界面文案位置

| 范围 | 来源 |
| --- | --- |
| Web、桌面端渲染进程、API、浏览器扩展 | `packages/shared/src/i18n/` 下的共享目录（`zh-CN.ts`、`zh-TW.ts`、`en-US.ts`、`es.ts`、`de.ts`、`fr.ts`、`ja.ts`、`pl.ts`、`ru.ts`），为唯一事实来源。 |
| 桌面端主进程 | `apps/desktop/src/main/desktop-copy.mjs` 与 `desktop-menu.mjs` 维护按相同语言代码（`desktopLocales`）索引的独立表，因为主进程无法导入 TS 目录。 |
| Android（`apps/mobile`）、iOS（`apps/ios`） | 移动端 UI 通过 `@edgeever/shared/i18n` 解析，具备运行时目录回退及原生字符串目录支持。 |

语言代码与工具函数位于 `packages/shared/src/i18n/locales.ts`：`supportedLocales`、`matchSupportedLocale`、`resolveSupportedLocale`、`localeEnglishNames`（AI 提示词使用的英文名，如 "Reply in Polish"）。

## 规则

先解析出语言代码，再从目录读取文案。不要在代码中比较语言字符串（如 `if (lang === "zh-CN") ...`）。日期和数字使用 `Intl` 并传入语言代码格式化。

`packages/shared/src/i18n/hardcoded-locale-guard.test.mjs` 会拒绝 i18n 代码以外新增的硬编码语言比较；内容语言相关逻辑（字幕轨道、示例数据、仅部分语言提供的文档）通过显式白名单放行。

## 新增语言

1. 在 `locales.ts` 中：把代码加入 `supportedLocales`，在 `matchSupportedLocale` 中增加匹配分支（如 `xx` / `xx-*`），并在 `localeEnglishNames` 中增加条目。
2. 新增 `packages/shared/src/i18n/<code>.ts`，包含全部键。`catalog.test.mjs` 校验各语言键一致。
3. 在 `packages/shared/src/i18n/index.ts` 中导出，并在 `packages/shared/package.json` 的 `exports` 中加入 `./i18n/<code>`。
4. Web：新增 `apps/web/src/i18n/resources/<code>.ts`（重新导出），在 `apps/web/src/i18n/index.ts` 中懒加载（`isOptionalLocale`、`loadOptionalCatalog`、`fallbackLng`），并在 `apps/web/src/i18n/locales.ts` 的 `localeLabels` 中增加名称。
5. 桌面端主进程：把代码加入 `desktopLocales`，并在 `desktop-copy.mjs`、`desktop-menu.mjs` 的表中补齐条目。
6. 运行测试：`bun test packages/shared/src/i18n`，再执行 `bun run typecheck`。

## 新增文案

在同一次改动中把键加入全部九个目录；任一目录缺键时一致性测试失败。桌面端主进程显示的文案写入其独立表，同样覆盖每个语言代码。
