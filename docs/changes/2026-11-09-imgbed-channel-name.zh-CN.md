# ImgBed 指定渠道名称（桌面端）

[English](2026-11-09-imgbed-channel-name.md)

## 问题与结果

修复 [Issue #822](https://github.com/tianma-if/edgeever/issues/822)。CloudFlare ImgBed 允许在同一种上传渠道下配置多个渠道（例如两个 Cloudflare R2 存储桶或多个 S3 服务商），并通过上传接口的 `channelName` 参数选择其中一个。EdgeEver 内置的 ImgBed 图床只发送了 `uploadChannel`，所以图片总是落到 ImgBed 默认选中的那个渠道（未开负载均衡时是第一个），用户无法指定。现在"设置 → 图床 → CloudFlare ImgBed"新增可选的"渠道名称"。

## 行为

| 编号 | 行为 | 验收 |
| --- | --- | --- |
| B01 | "渠道名称"为可选文本，最多 100 个字符，保存时去掉首尾空格（名称中间的空格保留）。填写后，上传和测试连接都会在请求中附带 `channelName=<名称>`；留空则不发送该参数。 | 桌面端 `imgbed.test.mjs`。 |
| B02 | 设置页在名称包含制表符、换行等控制字符时直接提示并禁用测试连接；主进程再次校验，非字符串、任意位置（包括首尾）包含控制字符，或去掉首尾空格后超过 100 个字符的名称会被拒绝，且不会发起请求。两端规则一致。 | 桌面端与 Web 端 `imgbed.test.mjs`。 |
| B03 | 渠道名称属于连接目标的一部分：修改后必须重新测试连接才能保存；只改首尾空格不算修改。旧版本保存的设置没有该字段，读取为空。 | 读取旧设置：Web 端 `picgo.test.mjs`；重新测试后才能保存：人工检查。 |
| B04 | 设置页说明：名称需与 ImgBed 管理后台中的渠道名称完全一致；留空或名称不存在时，由 ImgBed 自行选择渠道。 | 人工检查。 |
| B05 | 填写了渠道名称时，测试连接会先用同一个 Token 请求 ImgBed 的 `GET /api/channels`（与 `channelName` 在 ImgBed 同一版本加入，任何有效 Token 都可调用），确认所选上传渠道下存在这个名称的已启用渠道（区分大小写），再上传测试图片。名称不存在，或 ImgBed 版本过旧（没有该接口，返回 404 或网页而不是 JSON，这类版本也不支持 `channelName`）时，测试失败并显示"渠道名称无效"，不会上传测试图片；因此无法保存一个会被 ImgBed 静默忽略的名称。网络错误、超时、401/403、429、5xx 和响应过大等其他失败仍显示原有的连接失败或 Token 提示，不归咎于渠道名称。 | 桌面端 `imgbed.test.mjs`。 |
| B06 | 新增始终显示的"上传失败时自动重试"开关，对应 ImgBed 的 `autoRetry`（开启时，写入失败会先在同类型渠道重试，再换到其他类型的渠道）。用户没改过开关时，默认值跟随渠道名称：未填写时开启，与 ImgBed 服务端默认一致，现有用户行为不变；填写后关闭，指定渠道写入失败时直接报错，不会落到其他存储。用户改过开关后以用户的选择为准。上传始终显式发送 `autoRetry=true` 或 `false`。 | 桌面端与 Web 端 `imgbed.test.mjs`、Web 端 `picgo.test.mjs`。 |
| B07 | 填写了渠道名称时，测试连接始终发送 `autoRetry=false`，不受开关影响，确认指定渠道本身可以写入；该渠道写入失败时测试失败，不能保存。未填写名称时，测试连接按开关的值发送。 | 桌面端 `imgbed.test.mjs`。 |

## 范围与限制

- 填写了渠道名称、又手动打开自动重试时，正式上传在指定渠道写入失败后可能落到其他存储；测试连接仍会确认指定渠道本身可用。`autoRetry=false` 只关闭写入失败后的重试。
- 只在测试连接时校验名称。保存后如果在 ImgBed 后台重命名、禁用或删除了该渠道，ImgBed 会静默回退到默认渠道，上传响应也不说明实际使用了哪个渠道；此时需重新测试连接。
- 渠道名称需手动填写，暂不提供从 ImgBed 读取的下拉列表。

## 风险与回滚

只改动桌面端渲染进程的设置、上传参数和主进程校验，不涉及服务端、API、存储或 Migration。渠道名称留空时请求与之前完全相同，已有 ImgBed 设置无需迁移。回滚：清空"渠道名称"，或回退此改动。

未验证：针对真实多渠道 ImgBed 实例的上传；Windows 和 Linux 桌面端的交互检查；日语、波兰语、俄语、德语、西班牙语、法语文案未经母语者审校。
