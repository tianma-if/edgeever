# Issue #771：桌面附件外部编辑自动回存

[English](2026-11-04-attachment-writeback.md)

## 问题与目标

[#771](https://github.com/tianma-if/edgeever/issues/771) 要求从笔记打开附件，在 Excel/WPS 等外部应用中保存后自动更新原附件，不再另存并重新上传。基线为官方 `main` 的 `6be20cfc`：桌面端只创建独立本地副本；共享 API 已有带 `expectedContentHash` 的内容替换和条件更新。沿用桌面端范围，不解析或合并 Office 文档。

这是数据写入链路的高风险功能。价值是补齐外部编辑流程；最坏后果是上传保存中的内容或覆盖其他设备修改。用完整文件快照、已有哈希条件写入和持久化待回存内容控制风险。撤回桌面端改动即可停止新回存，无需数据库迁移；已经成功回存的内容不会因代码回滚而恢复，当前服务端不保留附件旧版本。回滚前应先复制未回存的本地文件，旧版不识别回存状态，仍可能按旧临时文件规则清理副本。Windows Excel/WPS、跨桌面平台及旧版升级到新版的真实链路必须单独验证，自动化和构建不能替代它们。

## 服务端文件名保留

现有附件重命名不改变内容哈希，而旧回存发送打开时的文件名，会撤销云端改名；笔记显示名称与实际文件名不同时也会触发。因此将原先“不改服务端替换契约”的边界收窄为允许 S6 的向后兼容扩展，不改变已有替换调用的名称语义。名称必须由数据库更新原子保留，不能用客户端先读名称再写入代替。

## 保持不变的边界

- 除 S6 可选参数外不改服务端替换契约；不改数据库结构、迁移、认证权限、上传大小或类型白名单；不改安装器、自动更新或发布流程。
- 不原地编辑正式附件缓存，不删除未成功回存的副本；原有历史打开副本没有可信基线，不自动补传。
- 不跟踪外部应用的“另存为”到其他路径，不实现 Office 插件、协作编辑、格式解析、文件内容合并或附件版本历史。
- 保持浏览器/移动端链接、下载、笔记编辑、已有离线新附件上传的入口和行为；不操作生产实例或用户真实笔记。
- Windows Excel/WPS 保存、断网后恢复、双端冲突及真实跨版本链路是平台验收项；在缺少对应环境时明确保留缺口。

## 完成核对

- S1/S2：现有打开入口接入受管理副本；以文件元数据稳定性和读取前后对照取得不可变快照，按原资源 ID 条件回存。重复副本在当前账户目录内串行预留名称，追加本地序号；云端文件名、资源 ID 不变。原路径替换、多次保存、上传中继续保存、零字节中间状态、超过既有替换大小、未修改文件及符号链接路径均有定向验证；新增回归覆盖连续重复打开与不同资源并发打开时的大小写/Unicode 同名冲突。
- S3：快照与基线存放在账户隔离的 `opened-attachments/open-*` 目录中（`.edgeever-writeback.json` / `.edgeever-writeback.pending`）；未确认回存的副本不参与七天过期清理，缺少可信基线的历史副本不会补传。断网、结果丢失、重启、账户切换、重新认证和冲突保护均有回归。独立 Node 故障注入覆盖真实 DOM 超时、读取时文件替换、内部快照锁、重试落盘乱序、同账户会话恢复、确认落盘失败及确认后清理失败；状态面板区分本地序号副本，IPC 异步完成后重新核对账户和发送者。冲突的“重试”仍使用原基线，不强制覆盖云端。
- S4/S5：真实共享 API/SQLite/本地对象存储验证原 ID 内容替换及独立 HTTP 客户端读取。macOS Electron 自动化走通打开入口、字节与文件大小刷新、再次打开、显示本地文件、断网后应用重启恢复，以及冲突面板与安全重试；截图已实际检查。状态入口位于桌面右下方、AI 按钮上方，Web/移动端不显示；中英及现有其他语言目录同步。
- 真实 WPS：macOS WPS Office 12.1.29182 已通过 XLSX 连续保存（金额 200→300、公式结果 220→320）、真实 Excel 97–2003 XLS 保存（金额 400、公式结果 420），关闭后从 EdgeEver 重开均读到新内容。XLSX 从服务端下载并检查单元格及 `SUM(B4:B5)`；XLS 服务端下载与 WPS 保存的受管理文件逐字节相同，数值与公式由 WPS 保存后及重开界面核对。编号副本可同时打开，第二份保存后服务端仍为原文件名，金额 500、公式结果 520；第三次打开显示 500。详见 [WPS 实测记录](evidence/2026-11-04-attachment-writeback/wps-results.json)。
- 验证：38 项本次核心定向/真实 API 回归通过，含现有资源路由、服务和上传集成共 59 项通过；已有附件 API、桌面资源仓库、事件和语言加载回归继续适用。主工程与移动端类型检查、Web/桌面前端及 Cloudflare Worker 构建、受影响文件 oxlint、diff 检查通过。完整方法、截图和边界见[验收证据](evidence/2026-11-04-attachment-writeback/README.zh-CN.md)。
