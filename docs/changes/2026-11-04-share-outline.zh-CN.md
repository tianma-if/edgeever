# 分享只读页文档大纲

## 问题与目标

Issue #775 要求 Web 分享只读页提供与编辑器一致的大纲：按标题层级导航、点击定位章节，并提供“折叠全部标题”和“展开全部标题”。普通 `/share/:token` 页面没有大纲；公开笔记本站点已有 H1–H4 基础大纲，但缺少批量折叠。

## 允许的变更清单

- 普通分享页和公开笔记站点复用同一套只读大纲。收集非空 H1–H6，与 `EDITOR_HEADING_LEVELS` 对齐，支持平滑定位和当前章节高亮。这替代原 H1–H4 限制，补齐编辑器已支持的标题层级。
- 保留公开笔记站点原有锚点算法：标题按 locale 转小写，将连续非字母／数字替换为 `-`，移除首尾连字符，再添加同名 slug 的出现序号；不使用 NFKC 归一化。加入 H5/H6 时保留原 H1–H4 的序号（包括空标题占用的序号），确保已分享的片段链接仍能定位。
- 桌面端显示右侧大纲，移动端提供抽屉；文档滚动时桌面大纲保持可见，公开页的 body/root 包装层不能成为不滚动的 sticky 容器，并保留图片预览的正文滚动锁；没有非空标题时不显示入口。
- 单项和全部折叠／展开只改变大纲树，不折叠正文，不将阅读状态写入笔记或服务端。
- 大纲条目保留片段链接语义，包括浏览器复制链接和打开链接操作；普通点击仍在页内定位。点击或初始链接所指向的标题位于只读正文折叠块内时，仅展开它的祖先折叠块，让目标章节可读；滚动高亮排除仍在折叠块中隐藏的标题。
- 跳转期间和结束后保留所选标题的高亮，包括文末短章节无法滚到视口顶部的情况；读者再次滚动正文时恢复按位置高亮，不使用固定超时释放。仅滚动高亮变化时不改写片段 URL。
- 保持正文渲染、正文内标题链接、图片预览、站点搜索和双向链接预览。
- 仅将 #775 的功能改动迁入上游 `main` 基线，不带入自部署 Fork 的快照历史或无关变更。
- 增加两种公开页面的浏览器回归测试，覆盖 H5/H6 导航与折叠、全角及重复标题旧链接、窄屏导航、无标题文档、链接语义、嵌套正文折叠块内的标题及文末短章节高亮；将此定向 spec 加入既有 WebKit 项目，以 Chromium 和 WebKit 验证抽屉关闭后跳转与旧链接直达，运行受影响测试、类型检查、lint 和 Web 构建。

## 保持不变的边界与风险

- 不修改分享 API、Token、鉴权、密码解锁、正文数据、依赖或数据库。
- 不修改编辑器大纲的行为或持久化。公开片段锚点与编辑器按标题文本匹配的正文链接属于不同的既有契约，不统一归一化算法。
- 最坏影响是 Web 只读页章节定位或大纲布局异常；撤回前端功能即可恢复原渲染，不涉及数据迁移。
- 必须验证上游基线上的修复版本；原 Fork 工作区的结果不能替代集成兼容性验证。

## 完成核对

- 两种公开布局均使用共享的 H1–H6 大纲；保留原 H1–H4 的锚点文本和序号，包括全角字符、重复标题和空标题占位。
- 上游基线前端连接本地 Demo API，以真实笔记和分享完成 Chromium 和 WebKit 各 8 项浏览器回归，共 16 项。两种布局均覆盖批量折叠不隐藏正文标题、H5/H6 定位、复制的旧链接、仅有深层标题的窄屏大纲、单项折叠、抽屉关闭后跳转，以及移除标题后隐藏入口。另验证了桌面大纲保持在视口内、图片预览滚动锁、链接语义，以及展开嵌套正文折叠块而不改变笔记修订号；隐藏标题不再被误判为当前章节。
- 文末短章节跳转和初始片段链接均保留目标高亮；读者再次使用滚轮或滚动键时恢复位置跟踪，滚动键也覆盖焦点仍在刚点击的大纲链接上的情况。滚动不会改写片段 URL。
- 既有公开笔记站点文章加载测试通过，包含正文内标题链接和图片预览；已目视检查桌面和窄屏渲染，并实际操作浏览器另开大纲链接。
- `evidence/share-outline.png`、`evidence/share-outline-collapsed.png` 和 `evidence/share-outline-mobile.png` 使用在桌面客户端中新建、并同步到真实 Cloudflare 实例的实用长笔记。本地候选前端读取该实例的公开 API，完整渲染 21 个 H1–H6 标题；折叠大纲后，正文仍保留全部 21 个标题。云端实例仍运行原版本。
- `evidence/share-outline-final-section.png` 使用同一篇云端真实笔记，显示正文已滚到页底时，大纲仍高亮所选的倒数第二节；继续滚动正文后，高亮恢复到末节，URL 仍指向所选章节。
- 标题树与正文标题链接共 9 项测试通过；根目录和移动端类型检查、Web 构建、变更文件 lint 与空白检查通过。
- 版本仅包含功能、浏览器回归和本双语变更清单；不包含 Fork 快照改动、API 变化、依赖变化或迁移。
