[English](README.md)

## 三种来源的实际导入

Web 设置入口及此前隔离的原生运行时已验证以下自造来源样本，目录、正文、标签、原始时间和附件完整字节均可读回，图片与 PDF 可阅读：

| 来源 | 来源笔记本 | 笔记 | 笔记所属资源 |
| --- | ---: | ---: | ---: |
| Evernote 11.40.2 ENEX | 1 | 1 | 5 |
| Obsidian 1.14.5 Vault | 4 | 6 | 6 |
| Joplin 3.7.21 JEX | 3 | 5 | 6 |

测试夹具及其来源见 [真实来源样本](../../../../tests/fixtures/note-import/real-apps/README.zh-CN.md)。集成测试还覆盖 Joplin RAW、普通 Markdown / Front Matter、目录与 ZIP。ENEX 保留现行待办状态、代码块和两行表格；Obsidian 保留根路径优先级、字面百分号和目录内压缩附件；Joplin 保留包内层级、标签关联及合法的缺失祖先边界。

- 预检取消零写入；超出 24 个的标签按来源顺序忽略并警告，不阻止导入。
- 同任务失败重试不重复创建笔记或附件；未知提交状态不盲目重放。并发人工编辑不被最终链接更新覆盖。
- 隐藏弹窗或切换设置后仍可恢复运行中的任务。实际 Web 中，附件失败后打开未完成笔记、返回设置，仍能同任务重试并完成；显式关闭结果才清理任务。成功、失败、取消和清理异常路径均释放同步暂停并刷新已写入内容。
- 图片外层链接、独立标题及资源 URL 后缀通过编辑、保存、重开和导出读回；普通 HTML anchor 不被改写。

## 平台与升级范围

- macOS：Electron 44.7.0 开发壳及 Rust sidecar，使用隔离用户目录，导入、附件读回和同步恢复通过。
- Linux：Ubuntu 25.10 x86_64 / Xvfb，官方 v2.16.1 运行时配合导入功能渲染器。三来源导入后，失败重试、取消及完整重启读回通过；16 篇验收笔记和 22 个缓存资源保留。
- Cloudflare：此前合并上游 2.16.1 的候选完成既有实例升级与三来源实际导入。`0072` → `0084` 保持 4 篇既有笔记及 1 个资源，5 个默认笔记本配色按上游 `0078` 清除。当前 R27–R30 的 API/Web 及 `0085` 已部署，升级前的 18 篇笔记、19 个笔记本、23 个资源和工作区业务字段保持一致；既有登录会话、健康检查和 OpenAPI 探针通过。线上设置入口再导入 1 篇 ENEX，原始时间、标签和 5 个附件字节一致，PNG/SVG 加载且 PDF 可阅读。
- 同一数据库从原 API 基线升级后，已有正文、标签、时间和资源字节保持一致。Docker 驱动的接口检查不等同于 Docker 容器部署验收。

旧原生候选不覆盖最新图片/列表及 R31–R41 修复；R31–R41 和 `0086` 尚未部署到 Cloudflare。Windows 原生、移动端真机、旧客户端编辑、AppImage 安装及跨版本自动升级仍未验证。当前 Cloudflare 验证未重新输入密码登录，Web ZIP 的本机保存也未完成；这两项需用户通过登录页和导出入口确认。

## 大库与额度

以下均为本地测量，不是线上 D1 账单或 Worker CPU 数据。

### D1 原生行数对照

真实 API 与本地 workerd D1，完整 Schema 至 `0085`，未预先执行 `ANALYZE`。自造数据包含 4,047 篇笔记、9 个笔记本、42 个修订、38 个资源和 6 个提示词。仅在隔离数据库副本中增加 `(workspace_id, id)` 候选索引，用 `meta.rows_read` 对比完整遍历；两边均不含会话认证和资源字节下载开销：

| 流程 | 现有 Schema 读取行数 | 候选索引后 | 降幅 |
| --- | ---: | ---: | ---: |
| 完整备份，164 页 | 1,356,449 | 50,073 | 96.31% |
| 首次同步，21 页 | 195,818 | 24,412 | 87.53% |

两边完整返回数据和顺序一致。备份原计划按创建时间索引的工作区前缀读取后排序，首次同步按归档索引的工作区前缀读取后排序；候选索引使笔记主分页直接按工作区和 ID 范围定位。索引构建读取 8,203 行、写入 4,048 行，数据库大小增加 224 KiB。

正式 migration `0086_memo_id_paging_index.sql` 已实现。另以目标和外部工作区各 1,000/4,000 篇固定正文笔记，通过实际备份/同步路由与本地 D1 核对规模增长；这组笔记没有资源或修订，认证和资源字节下载同样不计入：

| 流程 | 1,000 篇迁移前 | 1,000 篇迁移后 | 4,000 篇迁移后 |
| --- | ---: | ---: | ---: |
| 完整备份读取行数 | 91,226 | 12,265 | 48,985 |
| 首次同步读取行数 | 15,030 | 6,034 | 24,109 |

四倍笔记的读取分别增至 3.99/4.00 倍；迁移前后完整返回数据一致，外部工作区数据不混入。创建服务写入对照由 25 行变为 26 行；普通正文更新前后均为 26 行。索引只增加预期的新增笔记维护成本。Schema 升级回归还覆盖交错工作区 ID、已删除笔记、资源/修订和旧客户端默认响应；备份一致性、旧创建时间导出及同步契约的 32 项检查通过。

`0086` 尚未在线上执行，部署后的构建成本和完整流程用量仍待验证；实施边界与回退见[优化方案](../../../third-party-import-plan.zh-CN.md#9-d1-额度优化)。下方聚合行参与次数和 SQLite VM 指令保留各自测量口径，不能代替 D1 行数。

| 单目录导入笔记数 | 修前累计笔记聚合行参与次数 | R27 修后 |
| --- | ---: | ---: |
| 100 | 9,900 | 0 |
| 1,000 | 999,000 | 0 |
| 2,000 | 3,998,000 | 0 |

新建空目录仅返回一次完整统计；存在性校验不再统计目录中的笔记。子目录父级和复制笔记的相同读取放大也已移除。

| 完整导出笔记数 | 修前 OFFSET SQL VM 指令 | R28 后旧 OFFSET | R28 后新游标 |
| --- | ---: | ---: | ---: |
| 1,015 | 1,152,000 | 239,000 | 37,000 |
| 4,015 | 16,032,000 | 2,700,000 | 138,000 |

SQL VM 指令为近似值。新游标使用 `(workspace_id, is_deleted, created_at, id)` 索引；旧 OFFSET 仍保留累计跳过偏移的开销。真实 HTTP → 客户端 → JSON ZIP / Markdown ZIP 导出 79 篇笔记，包含 9 个资源、13 个修订；关闭来源服务后正文、标签、时间及独立附件字节一致。普通/加密备份、离线恢复和无变更定时备份通过。API/Web 与 `0085` 已部署到既有 Cloudflare 实例；线上 JSON 和 Markdown 导出各读取 3 页，均返回 19 篇笔记、28 个资源，无遗漏或重复，续页不重复返回总数。

### 当前候选的浏览器规模验证

macOS arm64、Ego Browser Chromium 156、开发 Web 的实际 Worker/IndexedDB 预检，输入为带时间元数据的独立小 Markdown 文件，不写远端：

| 来源 | 1,000 篇 | 4,000 篇 |
| --- | ---: | ---: |
| Obsidian | 2.6 s | 9.9 s |
| Joplin Markdown | 2.4 s | 12.2 s |

计数与输入一致，均无错误或警告，完成后无资源暂存块。来源数增至四倍，预检耗时约为 3.8/5.1 倍；这些测量覆盖预检，不代表线上逐篇写入吞吐。

真实 Worker → IndexedDB → 本地 D1 API 导入 96 篇各 256 KiB 正文（合计 24 MiB）耗时 17.5 s，96 篇均完成。全部结果序列化约 36.7 KiB，不含完整 Markdown、JSON、摘要或待确认正文，临时资源块为零。另有 SQLite API 的多篇 1 MiB 正文、响应丢失后的确认和人工编辑冲突回归通过。

单篇大正文仍受后端存储边界约束：[D1 单个字符串、BLOB 或行最多 2,000,000 字节](https://developers.cloudflare.com/d1/platform/limits/)。当前正文行同时保存 Markdown、JSON 和纯文本；本地 D1 的单篇 1 MiB 纯文本在导入和原有普通创建中均失败，导入返回 `SQLITE_TOOBIG`。这项已有存储限制未在本次改变，不能将大库测试表述为任意单篇大小均可导入；超限来源保留在原文件中，不能截断后计为成功。

### 实现基线的大附件测量

实现基线的大附件测量使用每项独立的用户目录，RSS 包含同进程 Worker，heap 仅包含主页面；测试字节可高度压缩，存储数值为浏览器物理占用估计：

| 输入资源总量 | 用时 | 峰值 RSS | 峰值 heap | 峰值存储估计 |
| --- | ---: | ---: | ---: | ---: |
| ZIP 1 GiB | 31.7 s | 1322.9 MiB | 131.7 MiB | 13.7 MiB |
| ZIP 4 GiB | 119.8 s | 1412.6 MiB | 154.7 MiB | 47.6 MiB |
| ENEX 192 MiB | 14.2 s | 1198.3 MiB | 135.4 MiB | 4.7 MiB |

三项完成后临时资源块均为零。大样本按需生成，不存入仓库：

```sh
bun tests/fixtures/note-import/generate-large.mjs /tmp/edgeever-note-import-large
```

## 任务状态与清理

本地空间在目录创建前失败时不写远端；创建后映射保存失败仍保留待确认状态，不重复建目录。确认后的 RAW Markdown 附件不全文扫描成笔记，无描述的资源目录笔记仍可导入。ENEX 同篇重复资源按篇清理，加密 ZIP 无法读取及初始化取消均及时结束；合法原型属性名附件上传和重试保持原字节、无重复。
