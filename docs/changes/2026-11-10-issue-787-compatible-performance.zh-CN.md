# #787：旧版兼容的表格性能基线

## 问题与目标

保留已验证的网格优化，单独冻结回退时不需要重写笔记的读取优化。公开表单和 MCP 表格操作会读取用不到的编辑器正文；公开表单页面还可能重复归一化同一批单元格。

## 允许的变更与验收

- 只需字段和记录数量时，不构造归一化的单元格对象。用于表格摘要、公开表单读取、附件字段检查和表主表单配置。保留字段、记录 ID、视图和异常值校验，对比 v1/v2 的摘要与完整解析器的拒绝结果。
- 这些表单路径及 MCP 读记录、字段预览和修改的首次读取，只查询同工作区、未删除笔记的表格源，不取编辑器 JSON 和索引文本。权限、字段、表满状态、分页、修订、标签不变；表单和 MCP 继续走原写入路径。
- 支持原生 Base64URL 的运行时对规范标记走快路径。保持标记精确字节及换行包裹兼容，其他环境和输入继续用原解码器。枚举表格附件时只遍历附件字段。

## 保持不变

不新增迁移、落盘编码、备份或表单提交协议，不改 Worker 绑定或重试。可读 Markdown 的字节不变，包括裸 CR。旧筛选排序、公开链接、v2 命名视图与旧离线草稿冲突保护不变。回到上一版网格代码无需改写数据。验证用同一卷从 Docker v2.19.0 升级，复用原表单并重放旧 v1 草稿。仍不稳定的近上限 D1 表单候选不在本次基线内。

## 完成核对

- Linux arm64 Docker 用同一卷从 v2.19.0 升到候选（0092）。旧 v1 字节和筛选顺序一致；原表单返回原配置并新增记录。带最新修订号重放旧 v1 草稿仍返回 409，两套视图与修订均未改变。
- 共享、表单及 MCP 定向测试通过。MCP 测试捕获实际 SQL，确认读记录和字段预览不查询编辑器 JSON 或索引文本。Web、自托管构建和主项目、移动端类型检查通过。
- 本次不修改或验收 Cloudflare 近上限表单。已保存 v2 命名视图的笔记仍须使用可读 v2 的服务端；回退此次性能改动不等于回退到 v2.19.0。
