# Generic Markdown file and folder import

[简体中文](2026-11-18-markdown-import.zh-CN.md)

See [#849](https://github.com/tianma-if/edgeever/issues/849). This plan also serves as the implementation checklist.

## Goal and baseline

On Web and desktop, users can choose a single `.md` or `.markdown` file or a regular local folder. They can choose a destination notebook and preview the actual destination, folder structure, and reference issues before writing. Links between notes imported in the same folder task can open the imported target. Everyday imports work without creating a ZIP or selecting Obsidian as the source.

The baseline is upstream `76bb3e80`. The Obsidian session already scans folders without `.obsidian`, preserves subfolders, uploads local attachments, and rewrites their links. Ten existing import tests passed, covering folder import, attachment readback, same-task retries, and note-count queries when importing 64 and 256 notes. The Obsidian file picker lists ZIPs, and the folder picker strips the selected folder name. Obsidian gives the vault root precedence in some path collisions and warns about inter-note links while keeping their original targets. [Import integration tests](https://github.com/tianma-if/edgeever/blob/76bb3e80/tests/note-import.integration.test.mjs#L253) · [Folder selection](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/web/src/components/settings/ThirdPartyImportDialog.tsx#L26) · [Reference resolution](https://github.com/tianma-if/edgeever/blob/76bb3e80/packages/shared/src/note-import/session.ts#L296)

## Implementation

1. Host the existing import dialog in the workspace and share one `NoteImportController` across Settings and notebook menus. Pass the source format, selected folder name, and initial destination into Markdown preflight. Keep the existing task, account, and instance bindings when either entry reopens a task.
2. Declare `markdown` as a distinct source in the shared types and existing server capabilities. Reuse `/api/v1/imports/memos`, its permissions, batch limit, and task idempotency key. If the server lacks the Markdown capability, show the existing upgrade guidance before creating any notebooks, notes, or resources. Older clients and existing import sources keep their current contract. No database migration is needed. [Import capability and write routes](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/api/src/import-routes.ts#L34) · [Capability check](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/web/src/lib/note-import/execute.ts#L28)
3. Reuse the Worker, task-scoped IndexedDB, Markdown parsing, and attachment uploader. Keep Markdown-specific handling in root-file placement, source-path resolution, and preflight text. Use the selected folder name for display and notebook placement and retain the original relative path for file identity. Read only needed attachments. Unreferenced non-Markdown files do not create notes. Saving uses the existing import metadata and editor conversion rules.
4. Reuse the executor's multipart uploads, same-task deduplication, content revision checks, and desktop sync pause and refresh. Revalidate the destination before writing. If it is gone, ask the user to select a destination to avoid writing to an unintended notebook. [Import executor](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/web/src/lib/note-import/execute.ts#L31)
5. In preflight, resolve note references to target entry keys within the task. After the per-note import, look up imported note IDs in the confirmed task results and use `createMemoLinkHref` only where the link can be converted. This handles forward and reciprocal links with the existing per-note failure and cancellation behavior. Keep pending link updates in the same task, reuse prior results on retries, and check the content revision before saving. Resolve target IDs through the task index. [Internal note links](https://github.com/tianma-if/edgeever/blob/76bb3e80/packages/shared/src/note-links.ts#L3)

## Product decisions

- Relative links between notes imported in the same task open the corresponding EdgeEver notes.
- Keep the selected source folder as a named notebook by default to group a whole-folder migration. Users can omit that level in preflight.
- Follow the Notion and SiYuan preflight behavior for missing attachments. Show the missing target, keep the original link, and let users confirm and import the note.

## Boundaries, verification, and rollback

- Keep the existing source boundary and file limits. Paths cannot be used to read files outside the selection. Use the editor's existing Markdown support. Word and PDF conversion, a general ZIP source, and lossless conversion of arbitrary Markdown extensions are outside the scope. Existing sources, permissions, backup, and sync contracts retain their current behavior.
- Keeping the source folder by default groups the imported notes for a whole-folder migration. Single files go directly into the chosen notebook. Settings uses the workspace's default filing notebook when available, or lets the user choose one. The existing workspace-root option is available when keeping the source folder.
- Inter-note links open the target note from the same task. For links with heading fragments or parameters, preflight shows the original target and clicking opens the note. Matching files across past imports, navigating to a specific heading in another note, and offline navigation inside an exported ZIP need separate definitions. Exports retain `#memo=…` links. The exporter still derives filenames from note titles and rewrites links to packaged resources. [Bulk Markdown export](https://github.com/tianma-if/edgeever/blob/926367d30d62a20677399409e14ac0730216ea73/apps/web/src/lib/markdown-export.ts)
- Use the same nested fixture in the actual Web and Windows desktop file and folder pickers. Capture the destination, preflight, and result screens, along with evidence of reopening, saving, and exporting. Keep screenshots and user acceptance notes outside the repository. Other environments do not satisfy Windows desktop acceptance.
- Measure cumulative database reads for the entire import in an isolated local instance. Start with the 64/256-note baseline, then test a populated destination with multiple child notebooks. Record note-count queries and local D1 `rows_read` where available. Keep the existing data and attachment configuration fixed and verify that reads grow with imported notes and folders without scanning previous notes once per item. Compare directories of the same size with and without inter-note links to measure the incremental reads and writes.
- Run affected import, path, controller, and editor round-trip checks and the repository's `bun run typecheck`, `bun run typecheck:mobile`, and `bun run build:web`. Verify zero import writes when the server lacks the capability.
- The main risks are partial writes, incorrect placement, wrong resource targets, and duplicates on retry. Control them with the preflight preview, exact path matching, task result records, and revision checks. Roll back the client entry and server capability to stop future Markdown imports. Already imported notes and attachments remain available.

## Completion checks

- The Web app connected to an isolated local Worker. Settings imported a single note, and the notebook menu imported the same nested fixture both with and without the source folder. Checks covered the preview and actual placement, original missing-attachment links, navigation in both directions, editing and reopening, and single and bulk Markdown exports. Attachment paths resolved inside the ZIP and the bytes matched the original. Browser fault injection verified that a delayed directory is discarded after switching dialogs, a failed notebook lookup blocks confirmation, manual refresh restores the full destination, and a valid folder drop still imports.
- All 168 affected tests passed. They cover existing sources, exact-path indexing, links within an import, retry after a target fails, recovery when a write response is lost, zero import writes against an older server, and protection against concurrent edits. A conflict on one note still permits independent link updates. Both type checks, the production Web build, and lint for changed files passed.
- Generic Markdown indexes exact paths and skips basename alias writes in preflight for 64 and 256 same-named notes. The link phase reads note bodies and uses the resource URLs recorded by the upload phase, which also cleans up temporary attachment chunks.
- Local D1 imported 64 and 256 notes under a destination with 100 existing notes. Reads rose from 1,819 to 6,427 rows without links and from 4,379 to 16,667 rows with one link per note. Each run executed four notebook count queries. Inter-note links add a revision-checked content update without recounting the notebook for each note.
- The packaged Windows desktop app still needs Windows acceptance for file selection, import, reopening, and export.
