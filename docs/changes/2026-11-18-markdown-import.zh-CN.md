# 通用 Markdown 文件和目录导入

[English](2026-11-18-markdown-import.md)

需求见 [#849](https://github.com/tianma-if/edgeever/issues/849)。本方案同时作为实施清单。

## 目标和现状

在 Web 和桌面端直接选择一个 `.md` / `.markdown` 文件或一个普通本地目录。用户可指定笔记本，在写入前看到实际落点、目录结构和引用问题。同一次目录导入中，笔记之间的链接可以打开导入后的目标笔记。日常导入无需打 ZIP 或选择 Obsidian 来源。

基线为上游 `76bb3e80`。现有 Obsidian 会话已能扫描没有 `.obsidian` 的目录，保留子目录、上传本地附件并改写引用。10 项现有导入回归通过，覆盖目录导入、附件读回、同任务重试和导入 64/256 篇时的笔记计数查询。文件选择器的 Obsidian 选项只列出 ZIP，目录选择会取掉所选目录名。Obsidian 的路径解析在部分冲突下优先 Vault 根，笔记互链仅提示并保留原文。[导入回归](https://github.com/tianma-if/edgeever/blob/76bb3e80/tests/note-import.integration.test.mjs#L253) · [目录选择](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/web/src/components/settings/ThirdPartyImportDialog.tsx#L26) · [引用解析](https://github.com/tianma-if/edgeever/blob/76bb3e80/packages/shared/src/note-import/session.ts#L296)

## 实施路径

1. 在工作区提供现有导入弹窗，让设置和笔记本菜单复用同一个 `NoteImportController`。把来源类型、所选目录名和初始目标带入 Markdown 预检。保留任务状态与账号、实例的绑定，点击另一入口时沿用已有任务。
2. 使用独立的 `markdown` 来源标识，在共享类型和服务端现有能力响应中声明。写入沿用 `/api/v1/imports/memos`、现有权限、批次上限及任务幂等键。服务端尚无 Markdown 能力时，显示现有升级提示并在创建目录、笔记和资源前停止。较旧客户端与既有来源继续使用现有契约。无需数据库迁移。[导入能力与写入接口](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/api/src/import-routes.ts#L34) · [能力检查](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/web/src/lib/note-import/execute.ts#L28)
3. 复用 Worker、任务级 IndexedDB、Markdown 解析和附件上传。Markdown 的差异集中在根文件放置、来源路径解析及预检文案。所选目录名用于展示和决定笔记本层级，文件身份按原相对路径保存。目录内只读需要的附件，未被引用的其他文件不生成笔记。保存仍使用现有导入元数据规则和编辑器转换。
4. 复用已有执行器的资源分片上传、同任务去重、正文版本检查和桌面同步暂停及刷新。目标笔记本在写入前再次校验，目标失效时提示重新选择，避免静默写入另一个位置。[执行器](https://github.com/tianma-if/edgeever/blob/76bb3e80/apps/web/src/lib/note-import/execute.ts#L31)
5. 预检将笔记引用解析为任务内的目标条目键。逐篇导入后，按已确认的任务结果查目标笔记 ID，仅对存在可转换链接的正文使用 `createMemoLinkHref` 改写。这样前向和双向引用都能解析，并能沿用原有逐篇失败和取消机制。未完成的链接更新保留在同一任务内，重试使用已有结果，写回时检查正文版本。定位目标只查任务索引。[站内链接格式](https://github.com/tianma-if/edgeever/blob/76bb3e80/packages/shared/src/note-links.ts#L3)

## 产品决定

- 同一任务中已导入的笔记可通过原相对链接跳转到对应的 EdgeEver 笔记。
- 默认创建所选源目录对应的笔记本，以保留整目录的迁移边界。预检时可以取消这一层。
- 缺少附件时沿用 Notion 和思源的预检策略。提示缺失的目标、保留原链接，用户确认后可导入正文。

## 边界、验证和回滚

- 沿用选中文件范围和现有文件限制，不跟随路径读取选区外文件。沿用 Markdown 编辑器支持范围，Word/PDF 转笔记、通用 ZIP 来源和任意扩展语法的无损转换不在范围内。已有来源默认值、权限、备份及同步协议保持原契约。
- 默认保留所选目录名，让一整批笔记集中在同名笔记本下，便于整目录迁移。单文件直接放入选定笔记本。设置入口沿用工作区的默认分类笔记本，若没有则由用户选择。保留源目录时，可用现有工作区顶层选项创建这一级。
- 笔记互链打开同任务的目标笔记。带标题锚点或参数的链接在预检列出原目标，点击打开笔记。按历史导入批次匹配源文件、跨笔记定位到具体标题、导出 ZIP 内离线跳转需要单独定义。导出保留 `#memo=…` 链接，仍按笔记标题生成文件名并改写打包资源链接。[批量 Markdown 导出](https://github.com/tianma-if/edgeever/blob/926367d30d62a20677399409e14ac0730216ea73/apps/web/src/lib/markdown-export.ts)
- 使用同一份多级目录夹具在 Web 和 Windows 桌面从实际文件/目录选择器导入。留存目标选择、预检和结果截图，以及重开、保存和导出证据。截图和面向用户的验收记录留在仓库外。其他环境的测试不替代 Windows 桌面验收。
- 用本地隔离实例测量整个导入的数据库累计读取。对照导入 64/256 篇的已有回归，再使用填充了旧笔记的目标和多子目录，记录笔记计数查询次数及本地 D1 `rows_read`（在支持该指标的环境）。固定已有数据和附件配置，核对读取量随导入篇数及目录增长，且每篇不会重扫已有笔记。使用同规模有互链和无互链的目录核对链接更新的增量读写。
- 执行受影响的导入、路径、控制器和编辑器往返检查，以及仓库要求的 `bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web`。旧服务端能力缺失时验证零导入写入。
- 最坏情况是部分写入、落错目录、引用错绑或重试重复创建。通过预检落点、完整路径匹配、任务结果记录及版本检查控制风险。回滚客户端入口与服务端能力即可停止该功能的新导入。已导入的笔记和附件继续保留。

## 完成核对

- Web 连接本地隔离 Worker，实际从设置导入单篇，并从笔记本菜单分别导入保留源目录和平铺的多级样本。核对预检与实际落点、缺失附件原链接、双向点击、编辑保存后重开、单篇和批量 Markdown 导出。ZIP 的附件相对路径可解析，附件字节与原件一致。浏览器故障注入验证了切换弹窗后丢弃迟到目录、目标列表失败时禁止确认、手动刷新后显示完整落点，以及正常目录拖放。
- Web 预检识别 HTML 本地图片及缺图。在预检后删除目标，通过原弹窗改选即可导入。重新打开笔记后图片可加载，从资源接口下载的字节与原件一致。
- 173 项受影响测试通过，覆盖原有来源、完整路径索引、同批链接、HTML 图片、写入前取消后改选、已有部分写入和创建结果不明时锁定目标、旧服务端零导入写入和并发编辑保护。遇到单篇并发编辑冲突时，剩余可写回的互链仍能完成。两项类型检查、Web 生产构建和改动文件的 lint 通过。
- 通用 Markdown 使用精确路径索引，64/256 篇同名笔记预检不再写入 basename 别名。互链阶段只读取正文，上传阶段已清理的附件分片无需再次清理。
- 本地 D1 在含 100 篇存量笔记的目标下导入 64/256 篇。无互链的累计读取从 1,819 增至 6,427 行，每篇存在一条互链时从 4,379 增至 16,667 行。四组各执行 4 次笔记本计数查询。互链增加一次受版本保护的正文改写，导入未逐篇重算笔记本计数。
- Windows 桌面打包版仍需在可用 Windows 环境完成文件选择、导入、重开和导出验收。
