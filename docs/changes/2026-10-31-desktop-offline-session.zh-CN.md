# 服务端故障时保留桌面本地工作区

## 问题与改动

桌面启动此前仅在 `navigator.onLine` 报告断网时使用已认证会话缓存。因此，服务器可达但返回 HTTP 500/503 时，已有本地工作区仍无法打开。另一条会话确认路径把请求失败和无效响应当作会话失效，可能清除缓存身份及安全存储的凭据。

`App` 现在统一通过经过测试的工作区会话加载函数启动。已有桌面账号遇到服务端 5xx、请求超时响应、限流、网络错误及无效会话响应时，保留本地访问，不再依赖操作系统的联网标志。本地编辑仍通过既有 SQLite 仓库和持久化同步队列保存。每个远端请求仍须经过服务端认证，此兜底不授予远端权限。

启动探测直接返回未认证结果，不清除正在执行的查询。后台发现会话撤销时，保留界面观察中的会话查询并清理其他账号查询，避免卡在启动页。只有明确的拒绝结果才确认会话失效；无法判断的结果保留缓存身份和凭据。确认请求按实例及凭据去重，旧请求不得使替换后的凭据或切换后的实例失效。有效的未认证会话响应或会话接口明确返回 401 仍要求重新登录。首次启动且没有缓存账号时，不放行离线访问。

## 风险与回滚

主要风险是使用错误账号身份，或在确认撤销后仍保留身份。实例、凭据检查及既有账号目录隔离继续生效。会话缓存格式、安全凭据存储、本地结构、迁移、同步协议和安装升级代码均未变更。撤回加载函数及确认逻辑即可回滚；不得删除本地数据目录或待同步记录。

## 验证

可重复运行的原生回归测试使用真实认证 API、隔离 SQLite、正式旧版桌面应用，以及修复后的应用包，并共用同一临时数据目录：

```sh
node tests/desktop-offline-upgrade.integration.mjs /path/to/old/executable /path/to/fixed/executable
```

测试先通过旧版 UI 登录并保存本地笔记，复现旧版在 HTTP 500 时退回登录页；随后验证升级后 UI 编辑、HTTP 503 下完整退出重启后的持久化、业务接口 401 且会话确认失败、服务恢复后上传全部待同步编辑，以及服务端真正撤销会话。截图和结果清单保留在输出的临时证据目录中，不访问生产服务或所有者的数据目录。

## 已执行的验证

- macOS arm64，正式 v2.16.1 的原生宿主及 sidecar，Electron 44.7.0 / Node 24.21.0。候选包仅替换生产构建的渲染端，保留正式版宿主和 sidecar，并完成 Developer ID 签名及 Apple 公证。两个应用仍显示 2.16.1，因为候选包用于测试，尚未正式发布新版。
- 同一份旧版创建的数据目录通过七项原生场景：登录与本地持久化；旧版 `http_500` 复现；500 下升级并通过 UI 离线编辑；503 下完整重启后继续编辑；业务接口 401 且会话确认失败；服务恢复后使用原凭据上传全部编辑；运行中及重启后真实会话撤销要求重新登录，重新认证后仍能打开原有本地笔记。
- 故障由回环地址测试服务返回真实 HTTP 响应，保留正常跨域头，底层使用真实认证 API 和 SQLite。未替换渲染端 API 方法或桌面桥接，不对生产 D1 压测，也不修改用户数据目录。
- 101 项 API 测试通过，包含首次启动不放行、无效响应、切换实例、明确拒绝，以及凭据替换中的延迟和并发响应。全量非 E2E 测试通过：4,566 + 17 + 24 项，macOS 跳过一项仅适用 Windows 的清理测试。Web/API 类型检查、移动端类型检查和 Web 生产构建通过。
- [原生结果清单](evidence/2026-10-31-desktop-offline-session/results.json)记录恢复后的服务端正文，及待同步、同步中、错误、冲突均为零。截图包括[旧版 500 登录页](evidence/2026-10-31-desktop-offline-session/old-500-login.png)、[500 故障期间本地编辑](evidence/2026-10-31-desktop-offline-session/fixed-500-local-edit.png)、[恢复后的工作区](evidence/2026-10-31-desktop-offline-session/fixed-recovered.png)。

本次未验证 Windows/Linux 原生执行、签名安装器替换或自动更新传输。没有新增数据库迁移、正式发版或覆盖安装用户应用。如果旧客户端此前已经清除了身份和凭据，本次改动不能安全地重建它们，仍需成功认证后重新打开该账号已有本地数据。
