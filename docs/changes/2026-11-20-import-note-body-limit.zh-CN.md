# 导入时的笔记正文超限提示

[English](2026-11-20-import-note-body-limit.md)

## 目标

在 v2.30.0 和本地 D1 上，单条长正文的 2.35 MB ENEX 可复现 [#868](https://github.com/tianma-if/edgeever/issues/868)。首次创建笔记返回 HTTP 200，单条结果为失败，错误为 `D1_ERROR: string or blob too big: SQLITE_TOOBIG`。导入弹窗显示写入结果待确认，目标笔记本中没有该笔记。

## 变更与验收

Web 和桌面共用的导入流程在首次创建的单条失败结果中识别 D1 的 `SQLITE_TOOBIG`，显示本地化的笔记正文超限提示，并明确标记失败。复用现有响应，兼容 v2.30.0 服务端。用导入集成测试重放实际响应，再通过 Web 向本地 D1 导入原合成样本，核对界面提示、导入数量和目标笔记本为空。

## 边界

导入格式、存储上限、接口契约、源文件内容和目标笔记本的创建行为沿用现有规则。同任务继续使用已有重试和幂等机制。其他失败沿用现有处理，包括首次创建丢失响应及附件或正文更新结果不明。使用现有集成测试检查首次创建丢失响应和同任务重试，并以同体积的短正文加附件 ENEX 验证正常导入。

误判会使用户对失败状态作出错误判断。只在单条创建失败结果中匹配明确的 D1 大小错误。回滚客户端改动即可恢复原行为。桌面打包版和报告者实例不在本地验收环境内。

## 完成核对

- Web 连接本地 D1 时显示「笔记正文过大，超出存储上限。」及「已导入 0 / 1 篇笔记」。接口返回原单条失败结果，目标笔记本中有 0 篇笔记。附件对照样本成功写入 1 篇笔记和 1 个 1,782,000 字节的附件。
- 导入集成和控制器的 109 项测试全部通过，覆盖实际 D1 响应、首次创建丢失响应后同任务重试无重复笔记，以及附件或最终更新结果不明的处理。两项类型检查和 Web 生产构建通过。
