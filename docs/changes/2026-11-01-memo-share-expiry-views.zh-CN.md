# 单篇笔记分享链接的有效期与打开次数

[English](2026-11-01-memo-share-expiry-views.md)

## 问题与结果

实现 [Issue #607](https://github.com/tianma-if/edgeever/issues/607)。单篇笔记分享链接会一直公开，直到所有者想起来撤销；所有者也无法知道链接是否被打开过。现在所有者可以为链接设置可选的有效期，并查看链接被打开的次数。未设置有效期的分享与之前完全一致。

## 行为

| 编号 | 行为 | 验收 |
| --- | --- | --- |
| E01 | Migration `0087` 为 `memo_shares` 新增 `expires_at`（UTC ISO，`NULL` 表示永久）、`view_count`（默认 0）和 `last_viewed_at`。现有记录保留令牌、密码、自定义地址和展示设置。 | Migration 测试比较迁移前后的记录。分别用旧版本创建的自托管数据目录和本地 D1 数据库（各含一个受密码保护的分享）升级后，分享不变。 |
| E02 | `PATCH /api/v1/memos/:id/share` 在现有字段之外接受 `expiresAt`（带时区偏移的 ISO 时间或 `null`）。服务端统一转为 UTC；过去的时间返回 400 `share_expiry_invalid`。只修改有效期的请求不会改动密码。只发送 `{ passwordProtected }` 的旧客户端继续可用。 | API 测试覆盖设置、规范化、延长、取消、过去时间、格式错误和空请求，以及修改有效期时密码保持不变。 |
| E03 | 是否过期只由服务端判断。过期后，笔记内容（`GET /api/public/shares/:token`）、密码解锁和分享附件均返回 `410 share_expired`，不包含标题或内容，与已撤销或不存在链接的 `404` 区分。`/share/<链接>.md` 返回 410 和简短说明，服务端渲染页面不包含笔记。已过期的笔记不会被其他公开笔记链接。 | API 与分享页测试覆盖上述四条路径、404 情况和笔记间链接。 |
| E04 | 所有者仍能看到已过期的分享：重新打开对话框会显示过期状态，不会创建新链接。所有者可以延长有效期、取消期限或撤销分享。 | API 测试读取并重新提交已过期的分享；在运行中的应用里手动检查。 |
| E05 | `view_count` 和 `last_viewed_at` 只在实际返回笔记内容时增加：通过密码门禁后的分享 API，以及 `.md` 版本。密码提示、解锁失败、已过期链接、附件下载、`HEAD` 请求以及 HTML 外壳（浏览器通过分享 API 计数一次）都不计数。不保存任何访问者信息。计数不会修改 `updated_at`，因此分享列表顺序不变。计数写入失败不会影响阅读。 | API 与分享页测试分别检查每条路径的计数。 |
| E06 | Web 分享对话框新增“链接有效期”选择：永久有效、1 天、7 天、30 天或自定义日期（在所有者所在时区的当天结束时到期）。对话框显示到期时间、过期提示以及“已打开 N 次 · 最近一次 …”。设置 → 已分享的笔记显示到期时间或“已过期”标记以及打开次数。公开页面显示“此分享链接已过期”。所有已发布语言均有文案。 | 渲染与单元测试；类型检查与 Web 构建；在自托管服务上手动检查所有状态。 |

Android 与 iOS 会忽略新字段并继续正常工作。笔记本分享不在本次范围内。

## 风险与回滚

最坏情况：所有者依赖有效期，而应用被回滚到本次变更之前的版本。旧代码会忽略 `expires_at`，因此在重新部署本版本之前，已过期的链接会重新可以访问。计数为近似值：两位访问者同时打开会各计一次，刷新页面以及自动读取 `.md` 版本也会计数。回滚后新增列保留，旧代码仍可正常使用这些数据，已用旧版本在迁移后的数据上验证。不修改任何已有 Migration。
