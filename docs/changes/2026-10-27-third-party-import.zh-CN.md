# 第三方笔记导入变更清单

[English](2026-10-27-third-party-import.md)

关联：[Issue #657](https://github.com/tianma-if/edgeever/issues/657)。实现契约：[第三方导入方案](../third-party-import-plan.zh-CN.md)。

## 问题与目标

将原 Evernote 命令行指南入口扩展为 Web/桌面的联网追加导入，支持 Evernote、Obsidian 和 Joplin，保留目录、元数据、图片与附件。先预检再写入；同任务重试复用已创建对象，新的导入任务不自动合并旧数据。

## 保持不变的边界

- 保留 MCP 导入、普通编辑、离线队列、Rust 数据结构、同步协议、备份和加密恢复契约。除 R28/R39 的分页索引 migration 外，不新增数据库结构、全局必填配置或权限。
- 不新增移动端导入入口、跨次自动合并、退出应用后续传、Obsidian 插件或跨笔记语法转换、远程图片抓取及全库事务回滚。
- 不改变安装器、自动升级、版本号和发布/部署机制。既有 Cloudflare 升级复用原 Worker、D1、R2、管理员和认证 Secret；不重置密码或替换实例。测试使用自造来源和隔离目录，不修改个人知识库。

## 重要选择与演进

采用客户端解析、共享 API 写入，而不是另建桌面离线导入协议：这样 Web 与 Electron 共用行为，Cloudflare 与 Docker 共用业务代码，不扩大 Rust 和同步协议。索引只保存定位与元数据，正文和资源逐篇读取；结果只保存定位、版本与资源映射，避免结果页重新累积全库正文。

标签原先按超过 24 个阻断处理，现由 I07/R11 的规则替代：按来源顺序规范化后保留前 24 个，忽略其余并警告。这样保留 API 的既有保存边界，同时不因多余标签阻断整库迁移。Joplin 未导出的祖先按来源导出边界处理，而不是伪造目录；包内循环和非法父类型仍拒绝。

Markdown 位置识别和序列化复用成熟解析器，不继续维护正则全局替换或双解析适配。图片外链作为可选属性保留，以适配现有块图片 schema；列表空首段只在导出投影中处理，不改存储结构。依赖以锁文件和实际 TipTap 契约为准，不为本机依赖目录漂移升级解析器。

## 大库读取与导出

逐篇创建原先通过 `getNotebook` 重复执行 `COUNT/MAX`，单目录导入 N 篇的累计笔记行参与次数为 `N × (N−1)`。Web 导出原先逐页 OFFSET 扫描和排序。R27 改用轻量存在性查询；R28 为新版客户端采用索引续页，同时保留旧字段、排序、OFFSET 和备份一致性契约。

| 编号 | 允许改变的行为 | 验收 |
| --- | --- | --- |
