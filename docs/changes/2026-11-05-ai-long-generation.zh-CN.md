# 长文分段与续接、侧栏正文命令（#652 PR B）

[English](2026-11-05-ai-long-generation.md)

关联 Issue：#652

## 问题与目标

PR A（#791）之后，能读到上限的模型不再被 4096 截断；但读不到上限的网关、上限较小的模型，以及超出上下文窗口的长文，仍然一次做不完。结果不完整时虽然会提示并禁止替换，任务本身却没有完成。Web 和桌面侧栏的 `/translate`、`/improve` 与选区翻译走的是 Agent 对话，不受自动预算和截断保护约束。本 PR 按 #652 确认的范围实现 PR B：

- 翻译、校对、润色、简化、改语气等输出与原文相当的任务，单次装不下时按 Markdown 结构分段完成。
- 续写、扩写、自定义指令等依赖全文的任务，被截断后自动续接。
- Web 和桌面侧栏的 `/translate`、`/improve` 和选区菜单的“翻译”改走正文生成，结果作为侧栏对话中的一轮显示（与 Agent 对话一致），支持复制、插入、替换；最近一份未应用的草稿在本机刷新后可恢复。
- Android、iOS 的 AI 助手和 Android 编辑器选区面板支持同样的分段与续接，并显示进度和未完成的段落。

## 允许变更与验收

1. **分段计划（服务端 prepare，共享纯函数）**：
   - 分段规则在 `packages/shared/src/ai-generation-segments.ts`。基于 `marked` 词法分析，只在顶层块之间切分：标题跟随它后面的内容，空行跟随前一块；代码块、表格、HTML 块和数学块内部不切分；单个块过长时先按列表项再按句子拆分。各段拼接后与原文逐字相同；CRLF 或混合换行的笔记先按 LF 切分，再在原文的相同位置截取，保留原有换行。
   - Front matter 和纯代码段原样保留，不发请求。
   - 是否分段：预估输出超过可用输出上限的 80%、输入装不下，或读不到上限且原文较长（每段约 2000 token 原文）时分段；手动预算按手动值计算。
   - 新客户端请求 prepare 时带 `segmentation`。需要分段时，prepare 返回 `segments`，不再对输入过长返回 413。每段 prepare 带 `segment`（段序号、标题路径、上一段原文和结果的结尾），服务端在指令里说明“这是第 i/n 部分，只处理这一部分”，并附上下文。
   - 与 #652 中的原设计相比，分段计划改为由服务端计算并返回三端（已在 #652 说明原因）。服务端只做文本切分，不调用模型。
2. **客户端编排（`packages/client`，Web、桌面、Android 共用；iOS 用 Swift 实现同样规则）**：
   - 逐段 prepare 并直连模型，按顺序合并；每段开始时发 `progress` 事件，段结束时用 `text-reset` 校正整份草稿。
   - 某段被截断或装不下时，按 `segmentation.depth` 让服务端把这一段拆小重试，最多两层；仍完成不了时保留该段原文，在完成事件的 `incompleteParts` 中列出。只要有未完成的段，草稿就不能替换原文。
   - 其他任务被截断时，带上已生成内容的结尾（最多 2 万字符）发起续接，最多 3 轮，拼接时去掉模型重复的部分。续接只有实际追加了正文，才会解除截断状态；返回空内容或只重复已有内容时，草稿保持不完整并停止续接。上下文放不下续接时停止，草稿标记为不完整。
   - 只有服务端在 prepare 响应里声明 `longGeneration: true` 时才续接；旧服务端会忽略续接参数、从头生成，因此新客户端连旧服务端时不续接，保持 PR A 的行为。
   - 任一段出错、断流或用户停止时结束整个任务，已收到的文字保留为不完整草稿，已经完成的请求不会重复调用。
3. **侧栏正文命令（Web / 桌面）**：
   - `/translate [语言]`、`/improve`、技能按钮和选区菜单“翻译”在默认模型可用时走正文生成；命令后的其他文字作为用户指令。`/summarize`、选区解释和普通聊天仍交给 Agent，Agent 编辑笔记的能力不变。
   - 结果按生成时间显示在对话中：用户发出的命令（或选区翻译的引文）作为用户消息，草稿作为回复，下方显示进度、未完成提示和操作，包括复制、插入（选区后或笔记末尾）、替换（整篇或选区）、重新生成和丢弃。翻译没有指定语言时（如 `/translate`、“翻译”按钮和选区翻译），先在回复处用与 Agent 提问相同的表单询问目标语言：给出 3 个可能的语言（排除原文所用语言，优先界面语言对应的默认目标语言），也可在“其他”中填写，点“继续”后才开始；`/translate en` 直接按指定语言翻译。结果出来后不再提供切换语言。草稿不写入 Agent 对话历史。
   - 替换只对已完成且完整的草稿开放。整篇替换时如果笔记在生成后被修改过，需要再次确认；选区替换时如果原选区内容或整篇文档已变化（Markdown 源码模式同样比对整篇源码，避免相同文字移到原位置时替换错地方），改为询问是否替换当前选中的文字，没有选中内容时提示重新选择。
4. **草稿恢复（Web / 桌面）**：每篇笔记在本机只保留最近一份已生成、尚未应用的草稿，按实例和账号隔离（工作区由账号决定），应用或丢弃后清除；退出登录时取消正在进行的生成，并清除该账号在此实例上的草稿。正在生成的请求在刷新后结束，不跨刷新续跑。草稿存放在独立的 IndexedDB 库 `edgeever-ai-drafts`，主本地库 `edgeever-local` 的结构版本不变。
5. **移动端界面**：Android AI 助手、编辑器选区面板和 iOS AI 助手显示“正在生成第 i/n 段”，结果有未完成的段时提示“第 i 段未能完成，保留了原文”并禁用替换。文案覆盖 5 种语言。

## 保持不变的边界、风险与恢复

- 跨版本：
  - 新客户端连旧服务端：拿不到分段计划，也不会续接，按 PR A 的单次请求执行，截断保护照常生效。
  - 旧客户端连新服务端：不发送新参数，行为与 PR A 相同。
  - 本次没有数据库迁移。
- 最坏情况：
  - 分段翻译的术语和风格可能前后不一致。每段都带上标题路径和上一段原文、结果的结尾来缓解。
  - 分段和续接会增加请求次数、费用和耗时。界面显示进度，用户可以随时停止。
  - 某段一直完成不了时，结果里这一段是原文，界面会明确提示，并禁止替换。
  - 续接时模型可能没有严格从断点继续；客户端只能去掉开头重复的部分，无法纠正改写过的内容。
- 回滚：回退代码即可。草稿库是独立的 IndexedDB 库，旧版本不会读取它，也不受它影响。

## 实现与验收结论

- 自动化：
  - shared：切分规则（逐字还原、标题跟随内容、代码块/表格/数学块不切分、front matter 与纯代码段原样保留、长列表与长段落拆分、短代码块跟随前文、优先在标题处开始新段）、是否分段的判断、续接拼接去重、过短结果判定、草稿完成状态（含未完成的段）。
  - API：需要分段时返回 `segments`、短文和开放式任务不分段、旧客户端不受影响、读不到上限和窗口不够时分段而不是 413、单段的位置和上下文、被截断的段可再拆分、续接计入窗口、参数组合校验。
  - client：分段按顺序执行并带上下文、纯代码段不发请求、被截断的段再拆分且仍失败时保留原文并禁止替换、过短结果按未完成处理、出错和停止时结束、续接最多 3 轮并去掉重复、旧服务端不续接、端到端经 prepare 分段。
  - iOS 单元测试：与 client 相同的场景。
  - Web：命令解析、来源变化检测，以及侧栏接线和替换条件的源码断言。
  - Playwright（真实浏览器，本地开发环境，浏览器中模拟模型服务）：
    - `/translate en` 把 24 节长文分多段翻译，刷新后恢复草稿并替换整篇笔记；
    - 有一段始终被截断时保留原文、提示第 2 段未完成并禁用替换；
    - 选区翻译只替换选中内容，其余内容不变。
  - `bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web`、`bun run lint` 通过。
- 真实服务验收（预览实例运行本分支，本分支客户端直连模型；测试长文与 PR A 相同：40 节中文 Markdown，含 41 个标题、8 个代码块、40 个链接和 1 张表格）：
  - 读不到上限的 OpenAI 兼容网关：该网关不理会客户端传的 `max_tokens`，对 Claude Haiku 4.5 约在 8192 token 处硬截断。PR A 时，同一模型的全文润色在 8195 token 处被截断。本 PR 下，翻译和全文润色各分 13 段完成，均为正常结束、没有未完成的段；40 节全部保留，41 个标题、16 个代码围栏、40 个链接和 5 行表格无一缺失，无需手填预算。
  - 首轮验收发现两个问题，均已修复并复测通过：
    - 一段以代码块开头时，模型把这个代码块当成上一段的上下文而省略；
    - 一段从某节中间开始时，模型只返回了片段，丢失 4 节，却报告正常结束。
    - 修复方式：短代码块跟随前文；段落尽量从标题开始；分段指令要求返回全部内容；结果明显过短时按未完成处理。
  - 能读到上限（DeepSeek 官方，输出上限 393,216）：40 节翻译仍为单次请求（`max_tokens=45166`），结构完整。
  - 续接：DeepSeek 官方接口，临时设 4096 的手动预算，扩写 12 节笔记。首次请求在上限处截断，续接 1 轮后正常结束，12 节、链接和代码块完整，拼接处无重复。上述网关会忽略 `max_tokens`，无法构造截断，所以不用于这项测试。
- Android 真机（预览 APK，连接运行本分支的预览实例）：
  - 读不到上限的网关上，用 Claude Haiku 4.5 处理 40 节长文：AI 助手显示分段进度，完整完成后可以替换。
  - 续接，DeepSeek 官方接口，自定义指令“每节扩写到三倍”：
    - 手动预算 4096 时，三轮续接用完仍未写完，提示达到输出上限，并禁用替换；
    - 手动预算 8192 时，截断后自动续接，正常结束，可以替换。
- iOS：Fork 的 Actions 上构建和单元测试通过，包括分段与续接的 6 个用例。模拟器 UI 测试新增“截断后续接并可替换”场景，在 1 次运行中通过；另一次运行里它和“完整结果可替换”场景都在 App 启动、登录阶段超时，还没打开 AI 助手。其余 6 个场景两次都通过。
- 评审修复的回归测试：
  - CRLF 与 LF 切出相同段数并逐字拼回原文，混合换行和 CRLF front matter 同样正确；
  - 首轮截断后续接返回空内容、只有空白或只重复原文时，草稿保持截断并禁止替换（client 与 iOS）；
  - Playwright：Markdown 源码模式下删掉原选区所在行，使另一处相同文字移到原位置，点“替换选中内容”时要求重新确认且不改动笔记（去掉修复后该用例失败）；
  - 退出登录取消本窗口内所有正在生成的草稿，被取消的生成不再保存，并清除该账号在此实例上的草稿。
- 未验证：iOS 真机；桌面端复用 Web 页面，未单独打包测试。
