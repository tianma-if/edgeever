# #787：多维表格命名视图

## 问题与目标

[#787](https://github.com/tianma-if/edgeever/issues/787#issuecomment-6648458457) 的待办、项目和数据整理需要在同一表里保存不同的筛选和排序。现有笔记仅保存一个筛选集合和一个排序字段；旧解析器会丢弃未识别的属性，不能在 v1 文档内附加视图。

## 允许的变更与验收

- Web 与桌面端在表格上方切换视图，可新建、复制、重命名、删除；保留至少一个视图。名称为空不可保存。新建从空配置开始，复制保留规则。切换只改变本机当前笔记的选中视图，不写笔记。工具栏显示生效的筛选和排序数量；面板内修改直到应用才保存。沿用自动保存、字段与记录编辑、表单和导出入口。
- 按字段类型提供操作和值控件：文本/链接匹配，数字比较，日期比较、范围和按本机日历周一至周日计算的「本周」，单选匹配选项，复选框匹配勾选状态，附件判断有无。条件满足全部或任一，不嵌套。首批沿用每视图最多 8 条筛选，未填完的规则不可应用。按排序列表逐项比较，同值保留源记录顺序，空值最后；新单选排序按选项顺序，旧排序保持原义。同一字段只在一个排序列表出现一次。删除字段时清理各视图对应的规则；更改字段类型时清除已不适用的新规则，旧规则沿用旧表语义。
- 保留 Markdown 标记、单份字段和记录及完整 Markdown 降级内容。共享解析器读取 v1/v2；v1 原筛选和排序映射到默认视图，保留旧规则语义；切换、查看和仍能用 v1 表达的编辑不升级。只有保存不能用 v1 表达的配置才写 v2。连接实例首次升级表时须确认服务端已支持 v2；未连接实例的桌面本地工作区可保存。旧版 v1 写入不能覆盖已升级笔记（包括回传携带新修订号的情况），保留草稿并给出明确冲突。历史恢复仍恢复所选版本。发布先提供双读服务端；恢复时保留能读 v2 的服务端，不能直接退回只读 v1 的版本。
- 用 v2.19.0 的旧格式样本核对可见记录及顺序；用 Web 与同一桌面渲染器验证切换、重开；用真实 SQLite API 验证原公开链接提交匹配和不匹配记录及带最新修订号的旧格式回传。针对已升级表校验表单、字段/记录写入和普通编辑不丢配置。

## 保持不变

公开表单仅写原表记录、链接及字段绑定不变；CSV 仍导出当前视图可见记录，公开分享、移动端降级和 MCP 记录查询仍使用原表，视图不是权限。插件 API 保留 v1 形状：始终读取源记录，默认视图仅在 v1 可完整表达时投影；插件写入仍使用完整表格。沿用现有修订号/编辑会话和队列，不新增 SQL 存储、记录容量、服务端筛选、重试或自动合并。不做看板、甘特图、视图协作权限或新移动端编辑器。主要风险是旧写入覆盖或旧服务端无法读取新格式；真实 Windows 安装版、Docker 跨版本及 Cloudflare 验收分别依据实际运行环境报告。

## 完成核对

- 从官方 v2.19.0 Docker 镜像切换到候选镜像，复用同一 SQLite 数据目录（0087 → 0092）。候选镜像用仓库 Dockerfile 的运行阶段打包本次 Web 和自托管构建产物。原视图的可见记录和顺序不变；新视图保存后重启容器仍在。浏览器另验证了视图切换、复制、重命名、删除，调整副本的排序不影响原视图。
- 容器回到原地址后，原公开表单接收了符合和不符合筛选的记录，只有符合条件的记录进入周视图，原表记录和保存的规则均完整。v2.19.0 浏览器产生的离线草稿回传进入冲突并保留；持当前修订号和有效编辑会话重放该 v1 草稿，服务端仍返回 HTTP 409，表格内容和视图配置不变。桌面同步、插件记录写入和移动端 Markdown 降级通过定向回归。
- Web 和自托管服务构建、主项目和移动端类型检查通过。Windows 安装版和 Cloudflare D1 未做实机验收；发版前验证对应的升级链路。
