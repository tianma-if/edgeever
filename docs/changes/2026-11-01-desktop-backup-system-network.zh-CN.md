# 桌面备份遵循系统网络设置

[English](2026-11-01-desktop-backup-system-network.md)

## 问题与目标

桌面同步使用 Electron 网络栈，备份工作线程却使用 Node 的全局 `fetch`。在依赖系统代理的网络中，同步正常，首次自动备份连接 `/api/v1/backups/state` 超时。备份与恢复应遵循每位用户自己的系统网络设置，不硬编码代理地址，也不修改操作系统配置。

变更仅涉及桌面备份与恢复的网络执行方式，不包含笔记列表排序或分享功能。

## 允许变更与验收

1. 桌面备份网络请求使用 Electron 的 Chromium 网络栈，以及同步使用的同一个默认 session；覆盖备份状态、分页、附件下载及恢复请求、上传。保留显式 bearer 认证与 `credentials: "omit"`，不开始发送 cookie。未配置代理的用户仍然直连。
2. 归档生成、校验、加密和磁盘操作仍在主进程外执行。优先使用 Electron 已有的 utility process，以薄适配保留管理器的消息、取消、失败和终止契约。下载保持流式、分片上传保持有界，不缓存整个附件或归档，也不经主进程中转文件字节。保留既有非 Electron 测试/调用方的 Node worker 执行方式，不作为网络失败后的 fallback。
3. 保留调度、源未变化检查、保留数量、路径、备份格式、恢复确认、账号隔离、错误诊断及请求次数。不新增重试、超时、代理设置、证书例外、迁移或依赖。
4. 使用真实 Electron 运行时验证仅代理可达的测试实例及直连实例，覆盖导出、附件完整性、恢复、取消/失败及工作进程退出。以代表性附件验证流式资源开销、比较请求路径和次数，并复用现有相关备份测试。对本分支执行必需的 Web/移动端类型检查及 Web 构建。
5. 用本地候选验证真实 Cloudflare 桌面流程：读取既有备份配置，生成包含已同步测试笔记的归档，查看累计 D1 读取量，不对生产库全量扫描或压测；应用及备份设置保持可用。区分候选运行、安装与发布，不从脏工作区部署服务端，也不发布 Release。
6. 独立分支对齐最新上游 `main`，验证共享归档/客户端变化后的备份路径。新增可直接执行的备份网络测试命令及按相关路径触发的 CI，在 macOS、Windows、Linux 运行相同的真实 Electron 代理/直连场景；Linux 使用 Xvfb，CI job 仅在官方仓库分配 Runner。测试入口使用跨平台文件路径；测试环境与用户配置隔离，不增加产品网络重试、超时或代理设置。区分 CI 运行时结果与正式安装包验收。

## 保持不变的边界、风险与恢复

功能价值是连接行为一致，用户无需配置两套网络栈。主要风险是工作进程生命周期差异、流式与取消行为退化；最坏影响是备份/恢复请求失败或工作进程未退出。保留管理器的发布和校验保护，失败任务不得记为成功归档。回滚独立的网络适配与工作进程入口即可，无存储格式或配置迁移。

安装、自动升级、数据存储、认证及服务端协议不变。既有归档及备份配置必须仍可读取。保留实际安装应用和用户数据，使用独立候选并保留官方安装包。Windows/Linux 运行时行为及安装包签名须在对应平台/发布阶段验证；macOS 检查不代表跨平台验收。

## 实施决策

使用绑定默认 session 的 Electron utility process 与 `net.fetch`，既有备份算法和流式管线继续在后台执行。这样无需引入代理解析/代理 agent、个人配置或自行实现主进程流式中转。Node worker port 仅作为既有测试的运行适配，不在请求失败后回退。

真实 Electron 回归放在独立、按路径触发的 CI 工作流中，避免默认 Bun 单测误启动桌面进程，也不让无关 Web 改动承担三平台运行成本。三个平台都覆盖代理/直连和进程退出，因为本次变更替换了桌面工作进程运行时；安装包签名、应用内升级和发布仍由既有发布流程验收。

## 完成核对

- 桌面入口注入绑定 `session.defaultSession` 的 utility process；打包工作程序仅在该运行时使用 `net.fetch`。原有 Node 线程入口与可注入 worker 契约仍可用。管理器、归档/存储/认证逻辑和服务端代码不变。构建将 `electron` 保留为外部导入，测试脚本放入原本排除打包的 `tests` 目录。
- 实现前，原 Node worker 在仅代理可达的回归实例上因 `backup_failed / fetch failed` 失败。真实 Electron 的代理/直连场景均通过：自动调度导出、32 MiB 附件往返、到期但源未变化检查、确认后恢复、HTTP 503、取消以及五个工作进程全部退出。两种网络均发送相同的 47 次测试 API 请求；到期未变化检查未再次生成归档。bearer 头保留，session cookie 未发送。执行 `bun run test:desktop:backup-network`，命令会先构建工作程序；设置 `EDGE_EVER_BACKUP_ATTACHMENT_MIB=128` 可使用更大附件。现有 57 项备份管理器/IPC/Node worker 测试、两项类型检查及桌面 Web 构建通过。
- 128 MiB 代理场景完整导出并恢复成功。32 与 128 MiB 附件的主进程工作集均约 144 MiB，utility worker 峰值约 301、318 MiB。原 Node 线程方案在 32 MiB 场景下主进程峰值约 434 MiB；新方案主进程与 worker 各自峰值之和约 445 MiB。这些本地分进程峰值不一定同时发生，且不含网络服务；结果体现有界增长，而非在主进程缓存整份归档。候选测量中的 25 ms 定时器最大额外延迟低于 9 ms。[机器可读证据](evidence/2026-11-01-desktop-backup-system-network/results.json)。
- 本地候选复用了真实官方 v2.16.1 的既有配置、已开启的每周/保留一份设置，以及未修改的官方渲染代码和原生 sidecar。真实 Cloudflare 手动备份成功：175,373 字节、41 个 ZIP 条目，CRC 检查通过，包含此前已同步验收笔记的完整正文。下一次真实自动备份尚未到期，调度行为由隔离的 Electron 场景验证。连接与备份验证期间，D1 24 小时读取行图表约由 19.08k 增至 19.81k，包含普通使用和初始化，不是单次备份或大库读取成本；未进行生产扫描或压测。
- 双向范围核对：产品实际改动为运行时/factory 适配、桌面接线及构建中的外部 Electron 导入，均对应条目 1–3；测试、CI 与证据对应条目 4–6。未增加代理配置、请求重试、归档/状态格式、存储/认证机制、依赖或服务端变化。正式 v2.16.1 客户端可继续读取候选写入的成功备份记录与原有计划；这项兼容性验证使用候选运行，不是正式发布安装。三平台运行时须通过备份网络 CI，正式安装包、签名和跨版本发布验收仍属于发布阶段。
- 独立 PR 分支已对齐上游 `main`（`feff718a`）；更新后的共享归档与客户端下，57 项相关测试、2 个真实 Electron 场景、Web/移动端类型检查和桌面 Web 构建均通过。新增命令自动构建 worker；独立 CI 仅对相关路径触发并以官方仓库门禁保护 Runner，在 macOS/Windows/Linux 上执行同一代理/直连回归，保存请求/进程报告。fixture 使用跨平台路径，并在测试期限内终止、等待自己的 Electron 子进程后清理；这些限制不进入产品请求逻辑。
