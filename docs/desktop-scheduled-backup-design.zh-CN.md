# 桌面端自动备份与加密恢复设计

[English](desktop-scheduled-backup-design.md)

关联：[Issue #650](https://github.com/tianma-if/edgeever/issues/650)、[原始需求 #61](https://github.com/tianma-if/edgeever/issues/61)。更新日期：2026-10-27。状态：已实现；验收范围和未完成项见[实施清单](changes/2026-10-23-desktop-scheduled-backup.zh-CN.md#完成核对)。

桌面端定期把当前账号的知识库保存为独立归档，支持密码加密。用户把保存目录选在网盘同步文件夹内，即可由现有网盘客户端负责异地传输。原实例不可访问时，用户仍可通过桌面端连接新实例并恢复归档。

本期同时交付自动备份、手动触发、加密和解密恢复。关键取舍是沿用现有知识库格式，由桌面后台任务打包，不在服务端生成大文件；为避免分页导出遗漏数据，服务端增加一致性读取协议。

## 1. 备份范围

备份对象是当前实例、当前账号的**已同步知识库**，包括未删除的笔记、笔记本层级、标签、归档与置顶状态、现有修订历史、AI 提示词，以及这些笔记关联的有效附件。结构化正文和可阅读的 Markdown 副本都保留。

以下内容不纳入本期归档：

- 尚未同步到服务端的修改、离线待上传附件和回收站内容。
- 用户账号、登录凭据、API Key、实例部署配置、对象存储配置、公开分享和表单的发布配置。
- 仅以外部 URL 引用、没有登记为 EdgeEver 资源的文件。正文中的链接保留，但外部服务失效会影响这些内容。

设置页应在备份范围处说明“备份已同步的笔记和附件”。备份任务不主动提交本地待同步修改，也不在网络不可用时改用本地缓存凑出一份归档。网络不可用时保留上次成功记录，等待重试。

现有 SQLite 本地快照继续承担本机恢复用途，不与本功能混用。S3 直传（可选的 WebDAV 异地副本见第 12 节）、应用完全退出后的系统级调度、Web 端密码导出与解密、移动端原生入口均留在后续范围。Web 原有普通 ZIP 导入导出保留。

## 2. 默认配置和设置入口

桌面端“设置 → 数据与备份”使用统一的“备份与恢复”卡片，替代旧独立 ZIP 导出卡；Web 原导入导出入口保持不变。

| 配置 | 首版行为 |
| --- | --- |
| 自动备份 | 首次关闭；用户开启且配置有效后安排首次备份 |
| 频率 | 每周、每月；默认每周。已有每天、每两周配置继续有效，修改前以禁用选项显示 |
| 保存目录 | 系统 Documents 目录下的 `EdgeEver Backups`，允许通过原生目录选择器更改 |
| 保留最近 | 1、3、5；默认 1 份。已有的 10、20 份配置继续有效，修改前以不可选选项显示 |
| 备份加密 | 可选，首次关闭；开启时输入并确认独立的备份密码 |

顶部提供“立即备份”“从文件恢复”“打开文件夹”；其下显示上次实际成功备份、最近检查结果，以及下次计划检查或自动备份关闭状态。运行时可取消。手动备份点击后直接开始，自动生成本地时间戳文件名，沿用已保存的加密设置、保存目录和保留规则，自动关闭时仍可使用。仅加密密码不可用或核验中断的加密备份时提示输入密码；保留页面内进度、成功及失败反馈。

开启加密时，密码必须非空且两次输入完全一致；不自动裁剪空格或修改 Unicode 内容。保存后只显示“已设置密码”，不回显密码。修改密码时说明“新密码仅用于之后生成的备份”。

备份设置位于状态下方，默认折叠；本地备份列表常显，列出文件名、时间、大小和是否加密，每行可恢复或删除。删除须二次确认。设置在没有任务运行时保存；运行中先取消，避免任务使用的配置与界面不一致。

## 3. 后台执行和账号隔离

### 3.1 进程职责

- **Electron 主进程**管理配置、系统凭据、目录授权、调度和任务生命周期，通过受限 IPC 向设置页提供状态与操作。
- **独立后台任务**负责数据读取、ZIP 编解码、加解密、校验和文件写入。任务不依赖设置页挂载，也不依赖渲染器持续存活。
- **Web 设置页**只负责配置、进度与导入确认；不接收已保存的密码，不通过 IPC 搬运整个归档。
- **共享归档模块**保存平台无关的格式、校验和 ZIP 读写逻辑。文件选择、浏览器下载、Node 文件流与系统凭据留在各自适配层。

已有主进程生命周期和系统唤醒事件可以复用，不把备份注册成 AI 定时任务，也不为本功能增加 Rust 侧的第二套 ZIP 格式实现。

### 3.2 调度规则

应用启动、登录就绪和系统唤醒时检查是否到期，后台运行期间每小时检查一次。首次开启且没有成功记录时视为到期；错过多个周期只执行一次，不补历史份数。

下一次到期时间以上次完成的归档或无变化检查为调度锚点，按本机日历增加 1、7、14 天或一个月；月底按目标月最后一天处理。本机时区变化后重算。修改频率不抹去上次实际成功备份记录。

源身份与修订、配置和密码版本未变化，且当前目录仍有大小匹配的上次登记文件时，自动任务只记录“内容未变化”，不生成文件、不轮转，也不更新实际成功备份时间。缺少比较信息或文件时生成新包；手动备份始终生成新包。

每次只运行一个备份任务，手动触发与自动触发共用互斥控制。任务以低优先级运行，不锁住前台编辑。记录 `lastAttemptAt`、`lastSuccessAt` 和 `nextDueAt`，失败不推进成功时间；网络失败或数据变化后，自动重试最早在一小时后的检查中进行，手动重试不受该等待限制。需要重新登录、修改目录或解锁安全存储时，显示对应操作，不反复弹窗。

关闭窗口进入托盘后仍可执行；完全退出应用则取消任务，下一次启动再检查到期状态。休眠、崩溃或取消留下的未完成任务不会被当成成功。

### 3.3 隔离规则

配置、凭据和成功记录按实例与账号保存。每个本机备份集另有随机 `backupSetId`，不同设备不共用保留规则。

任务开始时固定实例 URL、账号、工作区、会话凭据、配置和目标目录。每个请求使用这份固定上下文，不在处理中读取可变化的全局账号配置。退出登录、切换账号或实例时取消旧任务；迟到的响应不能发布文件、更新新账号状态或触发清理。

## 4. 服务端一致性读取

现有 `/api/v1/backups/json` 使用 `OFFSET` 分页；导出期间删除记录可能导致后续记录被跳过。现有同步游标只覆盖部分实体，不能直接作为包含附件和提示词的完整备份版本。

本方案采用**工作区版本校验加游标分页**。它允许用户继续编辑，但只有导出期间没有相关数据变更的任务才能成为成功备份。不跨请求持有长事务，不在服务端保存归档或常驻备份任务。

### 4.1 工作区备份版本

通过新增递增 SQL migration，为 `workspaces` 增加 `backup_revision`，默认值为 0。数据库触发器在备份相关数据插入、更新和删除时递增所属工作区的版本，与原写入处于同一事务。

覆盖范围包括 `notebooks`、`memos`、`memo_contents`、`memo_revisions`、`resources` 和 `ai_prompt_templates`。无直接工作区字段的表通过所属笔记确定工作区；删除前取得所属关系，关联移动时覆盖受影响的两侧。导入还原、批量删除和后台修订清理同样必须触发版本变化。

版本只用于判断“是否变化”，不代表笔记数量，不复用或改变现有同步游标。数据库版本在 API 中以十进制字符串传输。

### 4.2 读取协议

新增备份读取协议，保留旧接口及其参数和使用条件：

1. `GET /api/v1/backups/state` 返回协议版本、当前用户与工作区、工作区身份、`backupRevision` 和范围内实体计数。
2. `GET /api/v1/backups/data` 接受 `kind`、游标和步骤 1 的工作区身份、版本，分页读取笔记本、提示词或笔记。笔记页包含对应修订和附件元数据。按稳定 ID 使用游标分页，不使用偏移量。
3. 每页读取前后校验身份与版本；不一致返回明确的 `backup_source_changed`，整次任务失败。附件下载完成后再次调用状态接口进行最终比对。

新接口沿用现有备份数据的身份与访问权限校验；工作区由服务端会话确定，不能由客户端选择他人的工作区。状态和导出响应禁止缓存，版本校验使用数据库主写视图，不能依赖滞后的副本结果。

附件按元数据中的字节数和已有 SHA-256 摘要校验；原记录没有摘要时，在读取中计算并写入归档，用于恢复校验。缺失、截断或摘要不符均中止任务，不跳过附件后报告成功。这里的保护范围是应用管理的数据，不包括绕过应用直接修改数据库或存储桶的操作。

新桌面端连接不支持该协议的旧服务端时，提示升级服务端，不能静默退回弱一致性导出；原有手动 ZIP 导出仍按原契约可用。

这一选择会增加数据写入时的版本更新开销。持续变化的工作区可能多次推迟成功备份，界面必须保留真实的上次成功时间。若需要持续写入期间也完成同一时点快照，应另行设计快照与对象版本保留，不能通过忽略版本变化实现。

## 5. 沿用业务格式并支持 ZIP64

普通归档保持 `edgeever-zip` 的现有 `formatVersion: 2`：

- `manifest.json` 记录格式、应用版本、导出时间和实体计数，保持 `includesTrash: false`。
- `notebooks.json` 与 `prompts.json` 保存目录和提示词。
- `memos/<id>.json` 保存笔记、修订和资源元数据。
- `notes/` 保存按笔记本组织的 Markdown 与相对路径附件。

不改成原方案示意中的另一套 `memos/*.md`、`resources/` 布局。可增加不影响旧字段解释的可选来源信息，但不把账号凭据或备份密码放进归档。

采用支持 ZIP64 的成熟编解码库，首选 `@zip.js/zip.js`，替换备份路径中不支持 ZIP64 的底层读写部分，不顺带替换其他功能使用的压缩库。它支持 ZIP64、流式处理及浏览器、Node.js 和 Bun，采用 BSD-3-Clause 许可证；实施时锁定版本并保留许可证声明。[功能与兼容性](https://gildas-lormeau.github.io/zip.js/) · [许可证](https://github.com/gildas-lormeau/zip.js/blob/master/LICENSE)

普通小归档继续生成兼容 ZIP，大归档按需使用 ZIP64。保留 ZIP v1、v2 的读取兼容和已有单附件、图片大小限制；旧归档中可空的资源摘要仍可为空，不追加新的必填字段。增加总归档容量不等于放宽上传限制。旧客户端不具备 ZIP64 或加密包读取能力时，需要使用新版桌面端恢复。

新桌面备份、大归档解析和附件恢复按块处理并传递背压，不能先把完整 ZIP 转成 `Blob`、`ArrayBuffer` 或 base64。解析按需读取 ZIP 目录和条目，避免把所有附件内容加载进内存。Web 手动导出在不支持流式保存的浏览器中，保留原有最多 128 MiB 的缓冲下载路径，不把新桌面能力变成旧用法的前置条件。

## 6. 加密容器和密码管理

### 6.1 固定首版密码套件

首版采用 Node 原生加密实现：`AES-256-GCM` 加 `PBKDF2-HMAC-SHA256`，派生 32 字节密钥，迭代 600,000 次。选择 PBKDF2 是为了复用平台实现、便于后续跨端互通；成本参数参考 OWASP 的 PBKDF2 建议，实施时仍需测量目标设备耗时，不因耗时而静默降级。[参数参考](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)

每份文件独立生成 16 字节随机 salt 和 12 字节随机 IV，认证标签为 16 字节。密码以 UTF-8 编码，不规范化或裁剪。文件扩展名为 `.edgeever.enc`，内容按以下顺序排列，多字节整数使用大端序：

| 字段 | 大小与值 |
| --- | --- |
| Magic | 4 字节，ASCII `EDGB` |
| Container version | 2 字节，`1` |
| Cipher ID | 1 字节，`1` 表示 AES-256-GCM |
| KDF ID | 1 字节，`1` 表示 PBKDF2-HMAC-SHA256 |
| Iterations | 4 字节，`600000` |
| Salt | 16 字节 |
| IV | 12 字节 |
| Payload | 完整 ZIP 字节流的密文 |
| Authentication tag | 16 字节，位于文件末尾 |

前 40 字节文件头作为 GCM 的 AAD。v1 读取器只接受上述套件和参数，不执行文件任意指定的 KDF 成本；未知版本或参数提示不支持。后续参数升级必须明确扩展容器兼容规则，不能改变已发布版本的解释。

整包 GCM 单次加密的 ZIP 输入不超过 `2^36 - 32` 字节，即 64 GiB 减 32 字节；超过时停止任务并保留旧备份。该限制来自 GCM 单消息上限，与 ZIP64 是否支持大文件是两回事。更大加密归档需要新的分块认证容器，不能重复使用同一 IV 绕过限制。[NIST SP 800-38D，第 5.2.1.1 节](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38d.pdf)

### 6.2 无人值守凭据

备份密码不发送到 EdgeEver 服务端或网盘。为支持自动执行，本机通过 Electron `safeStorage` 和操作系统凭据机制保存密码，文件与实例、账号绑定，不写入普通配置、`localStorage`、日志或备份目录。

Linux 必须检查实际安全存储后端；`basic_text` 不能用于保存自动备份密码。安全存储不可用或被锁定时暂停加密自动任务，用户可以解锁后继续，也可以输入密码执行一次、不保存密码。不能改为明文输出或明文保存密码。[Electron 安全存储说明](https://www.electronjs.org/docs/latest/api/safe-storage)

更换密码只影响未来归档，旧文件不自动重加密。恢复其他设备生成的归档只需要文件和当时的密码，不依赖原电脑的系统密钥。没有找回或重置旧归档密码的服务端入口。

## 7. 文件发布和保留规则

用户选择的是保存根目录，应用为当前本机备份集创建 `<backupSetId>` 子目录，设置页显示实际写入目录。“打开文件夹”打开该子目录。自动任务文件名采用 UTC 时间与随机备份 ID，例如 `edgeever-backup-20261023T020000Z-<id>.zip`；加密时后缀为 `.edgeever.enc`。手动文件名自动采用本地时间戳，不带随机 ID；按已保存的格式追加扩展名。同名拒绝，不覆盖已有文件。

一次任务依次完成以下操作：

1. 校验账号、凭据、目标目录和服务端能力，记录本次任务归属。
2. 流式导出并写入目标目录中的唯一 `.part` 文件。启用加密时，ZIP 字节直接进入加密流，不在网盘目录留下明文中间文件。
3. 校验实体计数、附件和最终源版本，完成 ZIP 及加密收尾，将文件刷新到磁盘。
4. 在同一目录原子发布并持久化完成记录与上次成功时间。自动任务使用随机名称改名；手动命名使用排他硬链接创建，冲突或不支持时失败。
5. 清理超出保留数量的旧文件，发送一次轻量系统通知。

任何发布前失败都取消流并删除本任务的临时文件，不更新成功时间，不执行历史清理。文件已发布但完成记录写入中断时，恢复流程先核对本任务记录和文件完整性，不把文件直接当成垃圾删除。

清理只作用于本机记录为已完成、属于当前备份集的文件；按完成记录中的时间排序，不按目录的修改时间推断归属。不跟随符号链接删除外部文件，不清理手动放入、其他设备或其他账号的文件。

新备份成功但旧文件清理失败时，保留成功状态，单独显示“旧备份清理失败”，下一次任务再处理。更改保存目录或关闭自动备份不删除原目录文件。新安装无法确认旧文件归属时，保留旧文件并创建新的备份集。

应用只报告“本地备份完成”。网盘是否已经上传、是否存在冲突副本、是否还有云端容量，由网盘客户端负责，不能显示未经确认的“云端备份成功”。

## 8. 解密和恢复

“从文件恢复”默认打开当前备份集目录，也允许选择其他位置；列表中的“恢复”直接选择对应文件。两者共用解锁、检查和确认流程，按文件头识别普通 ZIP 与 `.edgeever.enc`，不只依赖扩展名。

1. 识别容器版本。加密包提示输入密码；用户取消时不产生恢复写入。
2. 流式解密到应用私有临时目录，完成 GCM 最终认证后才允许解析和导入。Unix 目录权限为 `0700`、文件为 `0600`，Windows 使用当前用户私有数据目录及相应 ACL。明文暂存不进入网盘目录。
3. 完整扫描 ZIP，校验格式、条目路径、CRC、实体计数、关联关系、附件长度和摘要。认证失败提示“无法解密，密码不正确或文件已损坏”；未知版本单独提示。
4. 展示目标实例、目标账号和导入数量，说明同 ID 数据会覆盖、无关数据保留，等待用户确认。
5. 复用现有提示词、笔记本、笔记和附件恢复接口，保持原 ID 与现有工作区访问边界。修订 ID 已属于其他笔记时，整页在写入前拒绝；同 ID、同笔记可重复恢复。全部成功后刷新工作区。

GCM 的流式输出在最终认证前不能视为可信，因此禁止把解密中的记录提前写入数据库。[Node.js 认证解密说明](https://nodejs.org/api/crypto.html#decipherupdatedata-inputencoding-outputencoding)

导入后的网络失败可能留下已完成的批次，界面显示“恢复未完成”，保留原文件并允许重试，不宣称已自动回滚整个工作区。重复导入继续遵循现有按 ID 恢复语义。临时明文在成功、失败、取消后删除；崩溃后仅清理应用记录为自建的暂存文件。

恢复不联系原实例。验收时必须切断原实例访问，再把文件导入全新实例并打开恢复后的笔记和附件。

## 9. 影响、兼容和回滚

这是高风险的数据保护功能。最坏后果包括泄漏明文、生成不可恢复的归档、误删最后一份可用备份，以及版本触发器影响正常写入；不能把风险只归结为忘记密码或磁盘满。

影响范围包括桌面主进程与后台任务、共享归档模块、Web 设置与桌面导入适配、备份读取 API、新增 migration 和对应客户端协议。Cloudflare 与 Docker 共用一致性业务代码，仅由现有存储适配器处理运行时差异。

实施必须保留以下兼容关系：

- 原手动普通 ZIP 导出、ZIP v1/v2 导入和现有 SQLite 本地恢复入口保持可用。
- 一致性协议只约束新自动备份及其“立即备份”，不为旧调用方追加必填参数或升级前置条件。
- 不改变同步游标、笔记 ID、权限规则和旧 migration；新触发器需要验证真实旧数据升级后的编辑、同步、删除与恢复。
- 关闭功能即停止新任务，已发布归档与备份目录保留。回滚应用不删除新增列和触发器；若触发器本身有问题，使用后续修复 migration 处理。
- 已经生成的加密或 ZIP64 文件需要保留可读取它们的客户端。回滚到旧客户端不能作为新归档可恢复性的证明。

实现后的发布按功能版本处理，不在本设计中预分配版本号，也不修改安装器、自动升级或发布流程。

## 10. 实施顺序与验收

实施前将确认后的行为写入 `docs/changes/` 中的双语变更清单。以下步骤属于同一交付，不能在解密恢复缺失时单独交付加密自动备份：

1. 完成一致性协议与迁移，验证旧数据升级和新旧客户端契约。
2. 抽取共享归档能力，完成 ZIP64、容器编解码与旧 ZIP 兼容。
3. 完成账号隔离、凭据、后台任务、原子发布与保留规则。
4. 接入设置和恢复入口，完成实际灾难恢复流程。

验收围绕以下行为选择最小充分范围，复用已有备份与恢复测试；新增自动化检查先于对应实现。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 普通与加密灾难恢复 | 原实例不可访问时，通过实际桌面入口恢复到新实例；笔记结构、修订、提示词和附件与备份范围一致，正文和附件可打开 |
| 旧版本升级 | 真实旧库升级后仍能编辑、同步、删除和恢复；原 ZIP v1/v2 可导入，原调用方无需新参数 |
| 数据并发变化 | 导出期间增删笔记、修改提示词、清理修订或变更附件，任务明确失败且不轮换旧备份；稳定数据可成功 |
| 后台生命周期 | 关闭设置页、窗口进入托盘、渲染器重载、系统休眠后唤醒，状态不重复执行；应用退出取消，错过周期只补一次 |
| 账号与目录隔离 | 切换实例或账号后没有混合数据和迟到成功；保留策略不删除其他账号、设备、手动文件或旧目录 |
| 密码和损坏文件 | 错误密码、头部篡改、密文篡改、截断、未知套件均不产生恢复写入；安全存储失效不产生明文备份 |
| 大归档 | 实际大于 4 GiB 的归档可导出和恢复，ZIP64 条目数量边界可读取；附件内容不随归档总量整包驻留内存；加密长度上限准确拒绝 |
| 文件失败与恢复 | 磁盘满、权限失效、取消、写入中断和清理失败，成功记录与历史文件符合第 7 节；明文暂存不会进入同步目录 |
| 桌面平台与服务端 | macOS、Windows、Linux 分别验证目录、凭据、文件发布和恢复；Cloudflare 与 Docker 分别验证一致性读取及 migration |

跨平台、跨版本和大归档结果分别记录，不能用单个平台的小文件测试代替。产品实现按项目要求执行 `bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web`；这些检查不代替恢复验收。

## 12. WebDAV 异地副本（P2，Issue #723）

可选的异地副本在本地备份发布完成后执行。本地归档仍是唯一可信来源；归档格式、服务端、数据库和同步均不变。

- **独立状态。** `backup-offsite.mjs` 在备份状态旁保存自己的状态文件（`<scope>.offsite.json`），从不进入本地备份队列。上传失败、服务器缓慢或上传被取消，都不会改变本地备份结果、成功时间或保留策略。
- **设置。** 默认关闭。地址、用户名、远程文件夹（默认 `/EdgeEver/backups`）和密码需要显式保存，并提供“测试连接”。必须使用 `https://`；由于 Basic 认证会在每次请求中发送密码，`http://` 只允许局域网地址。拒绝包含凭据、查询参数或片段的地址。
- **密码。** 与备份密码一样，用 Electron `safeStorage` 保存在独立的 `.secret` 文件中，并绑定实例和账号范围。密码不会出现在状态文件、渲染进程状态、日志或归档中，也不会发送到 EdgeEver 服务端。密码绑定输入时的地址和用户名：修改其中任何一项都必须重新输入密码，测试其他地址时也不会使用已保存的密码。系统安全存储不可用或 Linux 报告 `basic_text` 时暂停上传并提示，不回退为明文。
- **上传。** 已发布文件原样流式上传（加密归档保持加密）到 `<folder>/<backupSetId>/<name>.<uuid>.part`，请求带明确的 `Content-Length`，随后移动到最终文件名并核对远程大小。上传期间保持本地文件句柄，本地保留策略可照常执行。两分钟没有数据传输的请求会被中止；其他所有请求（创建文件夹、`MOVE`、核对大小、清理、保留策略和连接测试）也有同样的两分钟上限，即使服务器不响应取消也会结束，避免一个卡住的请求阻塞后续副本。失败时删除残留 `.part`；如果应用在上传中退出，下次启动时清理。
- **调度与重试。** 每次本地备份完成后排队一次上传，只保留最新的待上传归档。每小时检查时，如果最新本地归档上传失败或尚未上传，则重试（每小时最多一次）；“立即上传”会马上重试。切换账号、退出登录、关闭选项或修改目标都会取消上传。连接测试和上传只读取启动时所属账号的密码，等待期间账号发生变化即停止。
- **远程保留。** 使用本地保留数量。只删除本备份集记录为已上传到同一地址、用户和文件夹的文件，并且只在更新的副本上传成功之后删除。手动放入或其他设备、其他账号产生的文件永远不会被删除。删除失败显示为警告，稍后重试。
- **限制。** 标准 WebDAV 用单个请求上传文件。服务器请求大小限制（HTTP 413）会提示“文件超过该服务器限制”；各服务商的分块上传可作为后续改进。
- **回滚。** 关闭选项即停止上传，本地与远程文件均保留。旧版本会忽略额外的状态和密钥文件。
