# EdgeEver 猫爪模式：方案与取舍

[English](personality-memory-agent.md)

更新：2026-09-03。本文记录当前产品方向、实现边界与待验证事项；不是发布说明或开发日志。实现历史与验证记录保留在 Git 中。

## 1. 产品定位

Agent 是围绕用户知识工作的长期助手，不是一个熟悉笔记的聊天机器人，也不是通用电脑操作工具。它的价值在于发现零散记录之间的联系、理解用户长期关注的事情，并帮助完成笔记整理。

产品底线：轻量、快速、可靠。存在感不必强，建议必须有用；人格通过持续的理解、准确的记忆和有分寸的行动体现，不依赖拟人台词、情绪模拟或频繁打扰。聊天是辅助入口，不是功能主线。

当前主要体验：用户正常记笔记 → Agent 在合适时机发现机会 → 展示有来源的内容或操作建议 → 用户确认后执行。没有有价值的结果就保持安静。

## 2. 交互规则

- 入口为「设置 → 猫爪模式」，默认关闭。只有已配置并启用默认 AI 模型时才能开启；前端给出配置入口，服务端执行同样的模型可用性校验，模型不可用时仍可随时关闭。开启后，笔记访问范围覆盖当前账户的全部笔记，包括子笔记本和以后新建的笔记，无需选择笔记本；不代表一次读取或发送全库。
- 使用轻量铃铛和未读圆点，不占主导航、不自动弹窗、不发系统通知。当前仅向已登录的个人账户开放，要求非 Demo 且启用登录的实例；原生 Android/iOS 尚无入口。
- 普通通知提供有价值的关联、解释和来源链接，无须执行任务。操作通知说明处理哪些笔记、如何处理及其后果，用户确认后调用现有笔记能力执行。
- 建议不混入正常笔记，也不默认生成「AI 建议草稿」。只有确认了相应写入操作，才创建或修改笔记。
- 用户可忽略建议或关闭模式。关闭后未确认的发现操作失效；已经开始的确认操作保留执行记录，关闭不等于撤销已完成的修改。

设置页以简短用途介绍开头，再以只读状态呈现后台行为，不增加配置负担。状态面板展示猫爪处于安静观察、检查中、发现就绪或检查失败，最近检查时间、下次检查条件、数据范围与确认边界；存在生成结果时还展示最近一条发现：

> 开启后，EdgeEver 会像猫爪轻推纸片一样，帮你归拢零散碎片、将新想法沉淀到已有笔记、挑出过往的相关灵感。
>
> 用得越久，猫爪越懂你。

## 3. 当前能力与边界

| 路径 | 当前能力 | 边界 |
| --- | --- | --- |
| 主动发现：知识关联 | 唤回相关旧笔记，说明与新记录的联系 | 必须有来源；没有合适结果不通知 |
| 主动发现：合并 | 将属于同一想法的碎片归为一篇，保留原文、附件和标签 | 确认后执行；来源移入回收站并撤销原有分享，不承诺一键整体撤销 |
| 主动发现：补入 | 把新片段追加到已有笔记，保留来源和目标原文 | 当前仅支持无附件的纯文字笔记，不自动改写复杂文档 |
| 可选对话：笔记工具 | 28 项现有工具：13 项读取、15 项确认写入，覆盖创建、导入、修改、合并、移动、标签、回收站、版本恢复及笔记本整理 | 不等于主动发现会提出所有这些操作；永久删除、公开分享、二进制上传和系统管理未开放 |

「对话与个人记忆」仍是设置中的可选入口。当前对话有独立的笔记访问和记忆开关，笔记访问默认关闭；它与猫爪模式开关尚未统一。这是实现现状，不是要求用户额外选择笔记本，也不应被描述为全产品只有一个权限开关。

“具备笔记操作能力”意味着复用既有 API 和业务服务，而不是另写一套笔记系统，也不意味着模型获得无人值守修改权限。主动通知中的打标签等更多整理场景尚未接入，不能按完整工具目录对外承诺。

## 4. 人格与记忆

长期目标是让建议逐步体现用户的偏好、项目背景、共同决定和反馈。人格与记忆属于 EdgeEver 的产品数据和行为规则，不绑定某个模型，也不靠增加独立聊天入口体现价值。

当前已实现：

- 受产品控制的稳定身份；可选对话中的会话连续性与跨会话显式记忆。
- 用户通过界面手动添加记忆，或保存自己的原话，并可纠正、忘记、暂停使用；模型不能自行增删记忆。
- 基于分词、关键词权重和近期更新的小规模召回，不使用向量索引。记忆修改/遗忘会使旧上下文失效；用户确认的信息与模型推断不能混为一谈。
- 服务端按工作区和用户隔离存储；独立 JSON 导出包含记忆、聊天和整理记录，导入仅合并记忆，不恢复聊天和执行记录。

尚未打通：主动发现不读取个人记忆，不能宣称当前通知已理解用户的长期偏好。自动记忆候选、关系建模和基于长期反馈的建议调整也尚未实现。

下一步应优先验证“受控记忆能否让建议更相关”，而不是扩展人格配置。若接入主动发现，必须明确用户控制、来源、纠正和遗忘传播，不能静默扩大记忆用途。忽略一条通知也不应直接成为长期偏好。

删除笔记不等于删除聊天中的原文或快照，忘记一条记忆也不等于删除其来源。当前数据尚未纳入笔记 ZIP 备份、桌面离线镜像或原生移动端同步；不承诺完整跨端恢复，也不能代用户删除导出文件或模型服务商留存的数据。

## 5. 技术实现原理

整体是“客户端触发 + 服务端检索与模型判断 + 确认后执行现有业务”，不是在 Electron 中常驻一个自主程序。客户端负责交互与同步检查；模型调用、权限校验和数据持久化在实例服务端完成。

```text
客户端活动/同步/可见性事件 → 空闲检查 → 服务端限频与笔记变更检查
  → 检索少量相关笔记 → 模型返回结构化建议
      ├─ 无有用结果：结束，不通知
      ├─ 知识关联：保存发现记录 → 普通通知
      └─ 整理建议：保存发现记录和操作方案 → 带确认按钮的通知
          → 用户确认操作 ID → 重新校验 → 现有笔记服务执行 → 保存回执、刷新笔记
```

### 主动发现如何产生

1. 前端事件重置一次性空闲计时器，不使用常驻轮询；触发时先检查可见性、网络与待同步改动。服务端通过数据库条件更新占用本次检查，结合账户限频和工作区变更游标，防止多设备重复调用模型。
2. 以近期更新的笔记为线索，利用现有搜索查找相关记录，再在预算内读取正文。模型只看到选中的笔记，不直接连接数据库，也不会自动掌握整个知识库。
3. 按需创建 `ToolLoopAgent`，用 `Output.object` 和共享 Schema 约束结果：无建议，或一条 `insight / merge / append`。这一条路径不开放模型工具调用；模型负责判断关联和表达理由，服务端再次校验来源 ID、数据版本及操作条件。
4. 服务端为合并/补入构造确定的工具参数，将通知写入 `companion_discoveries`，操作方案写入 `companion_actions`；以类型和来源组合去重。它们是独立记录，不是普通笔记。客户端读取记录并展示两类通知。

### 人格、记忆与对话如何工作

可选对话将产品维护的身份指令、用户本轮输入、符合权限的近期会话、检索到的显式记忆和工具结果组合为模型上下文。记忆来自数据库，在用户允许使用时按相关性选入；不是训练模型，也不依赖模型服务商自动记住用户。当前主动发现不走个人记忆召回这条路径。

对话中的 `ToolLoopAgent` 可在步数预算内调用已开放的笔记工具：读取工具直接返回查询结果，写入工具仅保存待确认方案。工具目录复用 MCP 定义，但内置 Agent 直接调用共享业务执行器，不需要绕行外部 MCP 客户端。

### 涉及哪些数据表

Agent 专用表共七张，位于现有实例数据库中，不另建数据库。业务记录按工作区和用户隔离；`companion_action_checks` 是事务内校验用表，不保存用户内容。

| 表 | 用途 |
| --- | --- |
| `companion_discovery_settings` | 保存 Agent 开关、设置版本、检查时间、工作区游标及当前检查占用；`last_input_hash` 保存最近成功分析的输入指纹，减少重复调用。保留的 `notebook_ids_json` 不再用于选择笔记范围。 |
| `companion_discoveries` | 保存通知的类型、标题、正文、来源、去重指纹及已读/忽略状态；通过 `turn_id` 关联生成轮次，操作通知再通过 `action_id` 关联待确认方案。不是笔记表。 |
| `companion_turns` | 保存对话或主动发现的生成轮次：输入、回复、来源、模型、权限快照、上下文版本、运行状态和有效期；Token 字段在取得用量时记录，不代表所有发现请求已有完整计费统计。`origin` 区分聊天和发现。 |
| `companion_actions` | 保存待确认操作的准确参数及来源快照、状态、有效期、执行占用和结果回执；确认时读取这份记录执行，不让模型重新生成参数。 |
| `companion_state` | 保存账户的 `memory_revision` 上下文版本。记忆修改、遗忘或清空历史后递增，用来阻止旧上下文继续生成或执行。不是人格内容表。 |
| `companion_memories` | 保存用户明确添加的长期记忆、可选来源轮次、版本和时间；供可选对话召回，当前主动发现不读取。 |
| `companion_action_checks` | 在同一数据库批次中断言权限、上下文和数据版本仍有效；校验失败通过约束使批次回滚，成功则在提交前删除检查行。不是操作日志或任务队列。 |

身份指令和工具开放规则保留在代码中，没有单独的“人格表”。表结构见迁移 [0040](../migrations/0040_companion_memory.sql)、[0041](../migrations/0041_companion_actions.sql)、[0042](../migrations/0042_companion_tool_execution.sql)、[0043](../migrations/0043_companion_discovery.sql)、[0044](../migrations/0044_companion_discovery_input_hash.sql)。

### 为什么确认后可以直接执行

确认请求提交操作 ID，而非让模型重新生成任务。服务端读取之前保存的参数和来源快照，重新验证账户、状态、有效期与版本，再调用现有笔记服务。执行占用和写入检查随数据库批次生效，结果保存为回执；前端依据回执展示成功或不确定状态并刷新笔记。模型判断与实际写入因此分离，具体冲突和部分完成边界见下一节。

实现入口：[客户端触发](../apps/web/src/components/CompanionDiscoveryHub.tsx)、[发现服务](../apps/api/src/companion-discovery.ts)、[结构化生成](../apps/api/src/companion-discovery-runtime.ts)、[对话与记忆召回](../apps/api/src/companion-runtime.ts)、[工具目录](../apps/api/src/companion-tool-catalog.ts)、[确认执行](../apps/api/src/companion-tool-actions.ts)。

## 6. 技术与可靠性取舍

### 复用已有能力

保留 AI SDK `ToolLoopAgent` 和现有模型配置，由 EdgeEver 管理身份、记忆、权限、建议和执行记录。当前不引入 Mastra、ElizaOS、第二套数据库或自制通用 Agent/工作流框架。

工具名称和参数来自既有 MCP 目录，通过同一个业务执行器调用笔记服务；只增加 Agent 的开放策略、预览和确认适配。Cloudflare 与 Docker 共用业务逻辑。Agent 界面与服务端 AI 运行时按需加载，构建测试检查包括共享 chunk 在内的完整启动依赖链。

当前不新增运行时依赖、常驻自治进程或捆绑本地模型。没有新增依赖不等于没有包体、内存、模型费用和维护成本；实际增量必须测量，不使用早期不可复现的框架对比数字作保证。

### 曾参考的项目与未采用原因

- [ElizaOS](https://github.com/elizaos/eliza)：曾作为人格化、记忆与插件化 Agent 的参考。当前未采用，是因为 EdgeEver 已有笔记存储、插件和权限体系，接入另一套 Agent runtime 需要协调其记忆、状态与插件契约；这些适配成本尚未被当前的轻量发现和确认式整理需求证明合理。保留设计借鉴，不引入其运行时。
- [Mastra](https://github.com/mastra-ai/mastra)：曾评估其 TypeScript Agent、记忆、工作流与人工审批能力。当前未采用，是因为模型接入、工具循环和笔记执行已有可复用基础，当前流程还不需要完整的工作流编排；引入框架仍需实现 EdgeEver 专属的权限、版本校验和记忆治理，暂不足以抵消新增依赖及集成维护成本。

这是基于当前产品范围与既有架构的阶段性取舍，不是认定它们无法嵌入 Electron 或必然造成高资源占用。未来若需求超出现有方案的可维护范围，可重新评估，并以实际集成后的包体、内存和启动测量为依据。

### 有界成本

- 主动检查仅在应用打开、可见、联网、无待同步改动且停止操作 3 分钟后进行。跨设备共享限频，每账户每 24 小时最多尝试一次，笔记无变化跳过；客户端完成一次检查后，若没有新的笔记或同步变化，本轮会话不再重复请求。它不是全天候后台服务。
- 每次从近期记录和关键词查询中选择少量笔记，最多六篇正文、总计 12,000 字符；一次结构化生成，最多 1,200 输出 token、60 秒取消，不自动重试模型请求。
- 完整对话有独立的工具调用、上下文、并发和超时预算；授权全库不等于把全库放进 Prompt。
- 按需选出的内容会发送给用户配置的默认模型服务商。没有生成可展示建议也可能产生费用。关键词召回可能漏掉语义关联，低频检查也不保证及时发现所有机会。

### Token 开销控制

- 主动发现保存最近一次成功分析的输入指纹。后续检查即使被无关的工作区变化触发，只要候选笔记、提示词、语言、设置、上下文及模型配置版本相同，就跳过模型调用；无建议的成功结果也计入。失败不缓存，清空历史会清除指纹；不会重放旧结果或恢复失效操作。
- 发送给模型的笔记 ID 换成当次有效的短编号，输出由服务端严格映射回真实 ID。正文保持完整，不靠截断整理来源来节省 Token。
- 对话只召回最多八条相关记忆，总正文预算从 8,000 降到 4,000 字符；没有关键词匹配时最多保留最近两条。不删除已存记忆，但可能漏掉相关的旧偏好，需通过真实场景验证取舍。
- 同一轮已完整读取的笔记，再次读取只返回引用提示，复用该轮上下文中的正文；仍检查权限及数据版本，不跨轮缓存。用户确认操作沿用已保存参数，不另调模型。

这些优化复用现有 AI SDK，不改变默认模型、触发频率或确认权限。字符预算不是 Token 计量，实际费用取决于模型、语言和内容；不承诺固定节省比例。升级需应用 [0044 数据库迁移](../migrations/0044_companion_discovery_input_hash.sql)，仅新增可空指纹字段，不修改笔记内容。

### 确认与恢复

1. 模型提出建议，服务端校验来源和参数；主动发现的合并/补入参数由服务端构造。保存准确操作、理由和数据版本，提议不修改笔记。
2. 用户确认绑定该份操作，执行时不再让模型重新决策。检查账户、有效期、来源版本和同步状态；建议过期或数据变化后需要重新生成。
3. 复用事务、执行占用和持久化记录，防止重复确认和覆盖并发改动。连接中断后恢复或查询结果，不把生成文本当作成功回执，也不盲目重跑不确定的写入。
4. 多批次操作可能部分完成；取消不自动回滚已发生的副作用。当前工作区游标策略较保守，无关笔记变化也可能使其他建议失效。

笔记、记忆、附件和工具结果都是不可信数据，不能改变身份、授予权限或伪造用户确认。不开放 Shell、电脑控制、自动对外发送或发布；不因为“熟悉用户”放宽授权。

## 7. 待验证事项与后续优先级

- 建立真实笔记场景集：判断是否属于同一想法、是否值得合并/补入、关联是否有用；评估误报、打扰、采纳率和错误整理风险，而不是通知数量或聊天时长。
- 验证真实模型的结构化输出、工具调用、取消、来源准确性及 Prompt 注入防护；模型不可用时不得影响正常笔记读写。
- 测量 Agent 关闭、空闲、首次运行、连续运行及取消后的安装包、冷启动、CPU、RSS/堆和模型费用；分别记录客户端与服务端，参照[桌面性能基线](desktop-performance-baseline.md)。
- 在现有场景质量可靠后，再验证记忆驱动的建议、主动标签整理以及对话与猫爪模式的权限一致性；不要把这些文档目标当作已经完成的功能。
- 补齐备份恢复、删除传播与跨端体验。自动化、提醒、多 Agent 和更重的检索基础设施不是当前默认范围；只有真实需求与测量证明必要时再评估。

实现变更需通过相关测试、全量非 E2E 回归、`bun run typecheck`、`bun run typecheck:mobile` 和 `bun run build:web`。测试通过不等于建议质量或资源指标已达标。

零新增依赖是当前策略，不是永久禁令。新增依赖必须说明用户收益、资源增量、维护成本和退出路径；不能为了保持“零依赖”而重新发明通用框架。
