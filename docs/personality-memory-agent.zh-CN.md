# EdgeEver 猫爪模式：方案与取舍

[English](personality-memory-agent.md)

更新：2026-09-05。本文描述当前实现与验证边界，不是发布说明。

## 1. 产品定位

猫爪围绕日常笔记工作提供知识关联和整理建议。长期记忆必须影响后续建议，而不只是积累聊天记录。当前通过显式偏好和有证据的归档、标签规律实现这一闭环；不承诺理解用户的所有意图。

建议独立于正常笔记；没有有用结果就保持安静。合并、补入、归档和添加标签均需要用户确认后执行。确认复用现有业务服务，模型不重新生成参数，也没有无人值守写入权限。

## 2. 开关与界面

- 设置 → 猫爪模式。首次开启需要可用的默认 AI 模型；关闭模式、暂停学习和停止使用记忆不依赖模型可用性。
- “从操作中学习”只处理开启之后的操作；暂停及重新开启不会补学停用期间的历史。关闭猫爪也停止处理学习事件。
- “使用已保存的记忆”统一控制对话和主动发现。对话仍有本轮笔记访问控制，默认关闭。暂停学习保留记忆，停止使用不删除记忆。
- 旧账户升级不自动开启学习或主动发现记忆；需要在设置中明确启用。对话的记忆复选框同步这一全局设置。
- “对话与个人记忆”展示显式信息、候选推测、有效推测和冲突状态，以及操作证据。可以编辑和忘记。
- 整理卡片提供“不再建议这种整理”：针对来源笔记本记录明确偏好。普通忽略只关闭当前建议，不被解释为长期偏好。
- Web / 桌面提供界面。原生 Android / iOS 尚无猫爪入口；只有经过同一服务端业务并可靠归因的同步操作才可能参与学习，尚未完成原生端到端验证。

## 3. 当前能力

| 路径 | 能力与边界 |
| --- | --- |
| 知识关联 | 解释新旧笔记间的具体联系，至少两篇来源 |
| 合并 | 仅同一具体想法的片段；保留正文、附件、标签，来源移入回收站并撤销分享；不承诺一键整体撤销 |
| 补入 | 将纯文本片段追加到目标，保留两篇原文；不处理复杂文档或带附件的来源 |
| 归档 | 提出已有笔记本目标，确认后执行现有移动工具 |
| 添加标签 | 仅使用候选笔记中的已有标签，保留目标原有标签 |
| 可选对话 | 保留原有 28 项笔记工具与写入确认流程；显式记忆和有效推测均可进入上下文 |

## 4. 学习与长期记忆

采用现有 AI SDK、数据库和业务服务，不引入新的 Agent 框架、向量数据库或常驻后台进程。

第一版使用确定的证据规则，不调用模型给自己打置信分：

1. 在现有 `memo.move`、`memo.update`、`tag.add/remove` 审计中补充笔记本及标签前后值，不在笔记保存路径调用模型或更新记忆。
2. 空闲检查异步消费已经提交的审计。按工作区、用户过滤，仅使用可归因的用户操作；导入没有学习快照，工具执行标记为 agent，不作为主动习惯证据。
3. 学习“带某标签的笔记通常放入某笔记本”和“某笔记本中经常添加某标签”两类有范围的规律。
4. 至少三个不同笔记、三个独立时间段、跨两天的一致选择才使推测生效。同一十分钟内的批量操作至多贡献一次选择。事件 ID 去重，处理游标和证据写入同一事务。
5. 来源被删除、归类被改动、出现竞争目标或证据超过 90 天后重新评估；有冲突的推测不参与召回。这些阈值是初始产品规则，仍需真实场景验证。
6. 显式纠正转为用户确认的信息，后续学习不能覆盖。忘记学习规律会删除其证据并保存无正文的规则排除键，阻止旧证据及后续相同规律重新出现。

最多保存 50 条记忆，其中自动推测最多 30 条，给明确偏好留出空间。每次消费最多 50 个审计事件，每事件最多提取少量规律；回顾最多 2,000 条近期证据。预算可能使繁忙账户延后处理，不能保证所有行为都学到。

自动从自由对话提取偏好、抽象项目背景/关系建模、从接受建议中加权学习以及精确关联撤销操作，仍未实现。明确对话偏好可以通过“记住这句话”保存。猫爪自己的操作不用于正向强化，避免形成自我证明的循环。

## 5. 如何影响建议

主动发现通过多个关键词检索相关旧笔记，结合近期记录选取最多六篇正文，总计 12,000 字符。仍以最近更新的一篇为当前线索，尚未实现多线索轮转。

同一记忆选择模块供对话与发现复用：按有效状态、适用范围、关键词及时间召回，显式偏好优先于推测。最多八条、总计 4,000 字符；无关键词匹配时保留少量回退内容，不读取全库或训练模型。

模型收到选中笔记、相关记忆和已有笔记本。笔记、记忆都是不可信数据，不能改变权限或伪造确认。结构化结果返回笔记与记忆来源编号，服务端校验并保存准确操作方案；通知可显示采用的记忆。明确的“不再建议”规则同时在服务端过滤。

输入指纹包含记忆和笔记本上下文，避免用旧偏好缓存结果。记忆版本变化即使没有笔记变化也可触发重新分析，并使旧上下文及待确认操作失效。确认执行仍重查权限、版本、来源和同步状态；已完成操作保留回执。

## 6. 存储、删除与备份

新增迁移 [0045](../migrations/0045_companion_learning.sql)，不修改旧迁移：

- 扩展 `companion_memories`：类型、范围、规则键、状态，保留原显式记忆及版本。
- 新增 `companion_memory_evidence` 和 `companion_memory_exclusions`，分别存储证据引用和排除键。
- 扩展发现设置：学习与使用开关、学习游标、最近分析记忆版本。
- 扩展发现类型约束，迁移原发现记录并增加使用的记忆 ID。

记录按工作区和用户隔离。Cloudflare/D1 与 Docker/Bun SQLite 使用相同服务代码和 SQL。

独立 JSON 导出升级至版本 2，保留记忆类型和学习控制项。兼容版本 1 导入；版本 2 导入恢复控制项，合并记忆，但推测不带入可信证据，作为候选等待用户确认。笔记本范围、规则排除键和证据不跨实例重建，导入不恢复聊天或执行记录。

这些数据仍未纳入笔记 ZIP、桌面离线镜像或原生移动同步。删除笔记会撤销其学习证据，但不删除已有聊天快照；忘记不能删除用户导出文件或模型服务商留存。

## 7. 运行与成本

应用可见、联网、无待同步改动，停止操作三分钟后尝试检查。常规笔记变化每天最多检查一次；记忆变化可提前检查，最多每小时一次。按账户共享限频和并发占用。客户端不常驻轮询，持续没有新事件就不重复请求。规则学习不调用模型。

每次发现最多一次结构化模型生成、1,200 输出 token、60 秒超时，不自动付费重试。选中笔记和相关记忆发送给默认模型服务商；无通知也可能产生费用。字符预算不是 token 计量，不承诺固定费用或节省比例。

## 8. 验证与回滚

验证覆盖批量/重复操作、关闭与重新启用、隔离、冲突、纠正、遗忘传播、候选导入、记忆触发发现、归档/标签确认及旧 SQLite 数据库重开升级。另在隔离的本地 D1 中应用旧迁移、写入旧数据、升级 0045，并检查保留数据和外键。

必须运行全量非 E2E 测试、`bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web`。浏览器验证使用 Codex 内置 Browser。

尚未验证：线上 D1 升级、真实用户长期建议质量、真实模型成本和原生移动端跨版本行为。不能据此声称“不影响现有用户”或“不影响自动升级”。

关闭学习可停止新证据处理；关闭记忆使用可让发现退回笔记上下文。数据库保持向前兼容字段，不用破坏性逆向迁移回滚；降级旧代码前应关闭猫爪，避免旧客户端处理新增发现类型。已确认笔记操作不因关闭或回滚而自动撤销。
