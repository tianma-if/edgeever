# EdgeEver 视频素材库

[English](README.md)

这里保存可编辑、可单独导出的宣传素材工程，不自动拼接整部宣传片。按需导出片段，再到剪辑软件里完成配乐、节奏和最终转场。

## 第一个片段

`clips/logo-reveal/` 是六秒、1920 × 1080、30 fps、无声的白底品牌片段。首秒留白；Logo 和名称在第 1 至 2.25 秒进入；完整品牌组合保持到最后一帧，末尾包含一秒静止余量。它是有底色的画面，不是透明叠加素材。

需要 Node.js 22+、npm 和 FFmpeg。请在片段目录内执行（在产品根目录运行 npm 可能遇到产品自身的 overrides 配置冲突）：

```sh
cd marketing/video/clips/logo-reveal
npm run check
npm run snapshot
npm run dev
```

确认预览后导出：

```sh
npm run render
```

输出保存在片段内被忽略的 `renders/` 目录。脚本固定 CLI 版本，不需要执行 `npm install` 或修改产品依赖。首次运行会把 CLI 下载到 npm 缓存；缺少可用浏览器时，浏览器准备步骤可能下载 Chromium。预览和渲染在本地进行；未配置云端发布或自动渲染工作流。

## 增加片段

每个片段在 `clips/<名称>/` 下使用自包含工程，包含自己的 `index.html`、`hyperframes.json`、`compositions/`、`assets/` 和元数据。可复制首个工程的脚本并固定相同的 CLI 版本。目前没有需要逐个片段安装的依赖；以后确需额外包时，再维护局部依赖清单和锁文件。不要把视频工具加入产品根依赖或 `apps/*`、`packages/*` 工作区。

每个片段应记录尺寸、帧率、时长、音频、背景或透明通道、头尾余量、可编辑字段、素材来源和导出方式。默认使用 1920 × 1080、30 fps，有明确用途时再改变。导出前检查工程并查看开头、运动中和结尾静止段的快照。未来的透明素材必须验证实际透明通道和目标剪辑软件导入，才能宣称支持透明叠加。

## Git 与素材管理

提交 HTML/CSS/JS、制作方案、元数据、固定版本命令及少量必要且授权清晰的素材。原始录屏、渲染视频、快照、缓存和剪辑工程不进入 Git；`raw/`、`renders/` 和工具生成目录已忽略。大体积共用源素材保存在外部存储，并在这里记录稳定位置与授权。不要提交私人界面、凭据或受限制的第三方素材。

首个片段把产品的 `assets/brand/edgeever-mark.svg` 小体积副本固定在本地素材目录，使片段能够独立渲染。品牌变化时显式更新副本，不要通过视频工程修改产品 Logo。以后可在素材库层记录共用素材，但只把当前片段需要的资源复制到其渲染根目录。

## 自部署边界

- 本目录位于产品工作区和 TypeScript 输入范围之外。产品依赖清单与根锁文件保持不变。
- Docker 排除此目录；仅修改视频素材时跳过产品测试工作流，混合修改仍触发。没有新增视频 Actions 或安装钩子。
- 现有原生发布规划不把本目录视为运行时输入。
- Cloudflare Workers Builds 配置脚本为新建或重新配置的触发器排除 `marketing/video/*`。已有远程触发器不会随拉取代码自动更新；如需排除，实例所有者应在 Cloudflare 设置同样规则。本次搭建不修改远程设置。
- 其他外部流水线仍可能监听所有提交。已跟踪的源文件也会少量增加每个 Fork 的克隆体积，因此排除生成媒体，限制增长。
